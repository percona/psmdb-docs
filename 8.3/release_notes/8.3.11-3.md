# Percona Server for MongoDB 8.3.11-3 (2026-09-28)

[Installation](https://docs.percona.com/percona-server-for-mongodb/8.3/install/index.md) [Upgrade from MongoDB Community](https://docs.percona.com/percona-server-for-mongodb/8.3/install/upgrade-from-mongodb.md)

Technical Preview

Percona Server for MongoDB 8.3.11-3 is available as a technical preview.

We recommend that early adopters use this release for testing purposes only and not in production environments.

We are pleased to announce **Percona Server for MongoDB 8.3.11-3** – the drop-in replacement for MongoDB Community Edition. Percona Server for MongoDB supports MongoDB Community protocols and drivers and enhances it with the [enterprise-grade features for free](https://docs.percona.com/percona-server-for-mongodb/8.3/comparison.md), enabling you to effectively meet the requirements of your organization in terms of high-availability, reliability and data security.

Percona Server for MongoDB **8.3.11-3** includes the improvements and bug fixes of:

- [MongoDB 8.3.11 Community Edition](https://www.mongodb.com/docs/manual/release-notes/8.3/#8311---sept-11-2026) and [MongoDB 8.3.9 Community Edition](https://www.mongodb.com/docs/manual/release-notes/8.3/#839---sept-8-2026) .
- Supports protocols and drivers of MongoDB Community **8.3.11**.

## Upgrade recommendation

This release fixes multiple security vulnerabilities inherited from upstream MongoDB. We strongly recommend **upgrading to version 8.3.11-3** as soon as possible.

## Known issues

This section describes known issues in Percona Server for MongoDB 8.3.11-3 and their resolution status.

- [SERVER-136961](https://jira.mongodb.org/browse/SERVER-136961) : If a node has an unclean shutdown for any reason and then restarts to perform a [file copy-based initial sync](https://docs.percona.com/percona-server-for-mongodb/8.3/fcbis.md), the node crashes each time it restarts and cannot complete initial sync without manual intervention.

  This issue affects Percona Server for MongoDB 8.3.7-1 and later versions.

  To recover a node in a self-managed deployment, do one of the following:

  - Restart the node with the `initialSyncMethod` parameter set to `logical`.
  - Delete the contents of the node’s `dbPath` directory, then restart the node to begin a new file copy-based initial sync.

## Changelog

### Improvement

- [PSMDB-2199](https://perconadev.atlassian.net/browse/PSMDB-2199): Upgraded `mongo-c-driver` to version [1.30.10](https://www.mongodb.com/docs/languages/c/c-driver/current/reference/release-notes/#whats-new-in-13010) . This version includes a fix for [CVE-2026-6231](https://nvd.nist.gov/vuln/detail/CVE-2026-6231) .

### Bugs fixed

- [PSMDB-2253](https://perconadev.atlassian.net/browse/PSMDB-2253): Fixed an issue that caused a replica set member to crash during file-copy-based initial sync when KMIP encryption at rest was enabled. The crash occurred when the member started with an empty data directory and no `--kmipKeyIdentifier`. In this case, the member generated a new KMIP master key but could not use it to decrypt the `key.db/` files copied from the sync source.

## Security fixes from upstream MongoDB

The severity categories below follow the upstream [CVSS scores](https://nvd.nist.gov/vuln-metrics/cvss) .

### Critical severity

- [SERVER-131229](https://jira.mongodb.org/browse/SERVER-131229) ([CVE-2026-82067](https://www.cve.org/CVERecord?id=CVE-2026-82067) ): Fixed an issue in MongoDB Server’s configuration validation where incorrect handling of case sensitivity could leave authorization disabled during startup. If this occurred, an unauthenticated user with network access could perform administrative operations without authorization, potentially compromising data confidentiality, integrity, and availability.

### High severity

- [SERVER-134063](https://jira.mongodb.org/browse/SERVER-134063) ([CVE-2026-89099](https://www.cve.org/CVERecord?id=CVE-2026-89099) ): Fixed a race condition in the document value layer of MongoDB Server that allowed concurrent server threads to operate on the same internal memory without synchronization, leading to memory corruption. An authenticated user with read-write privileges could trigger this condition over the normal client protocol. This could result in server termination and potential corruption of process memory with user-influenced content. This vulnerability could compromise the confidentiality, integrity, and availability of the affected server process.
- [SERVER-128253](https://jira.mongodb.org/browse/SERVER-128253) ([CVE-2026-82076](https://www.cve.org/CVERecord?id=CVE-2026-82076) ): Fixed an integer overflow in the query planning component of MongoDB Server that allowed an authenticated user with ordinary database-level read/write privileges to bypass an internal resource limit. Submitting a specially crafted query caused the server to consume memory without bound during query planning, which exhausted the server process and caused a denial-of-service affecting all databases served by the affected node.
- [SERVER-132650](https://jira.mongodb.org/browse/SERVER-132650) ([CVE-2026-82075](https://www.cve.org/CVERecord?id=CVE-2026-82075) ): Fixed uncontrolled resource consumption in the request-handling path of the MongoDB sharded-cluster router process. An unauthenticated client with network access to a router port could supply connection-monitoring parameters that caused the server to expend CPU resources without rate limiting, resulting in performance degradation or denial of service for legitimate clients.
- [SERVER-132125](https://jira.mongodb.org/browse/SERVER-132125) ([CVE-2026-82073](https://www.cve.org/CVERecord?id=CVE-2026-82073) ): Fixed insufficient validation of an internal aggregation option. An authenticated user could bypass authorization checks and access collection data without the required privileges.
- [SERVER-131860](https://jira.mongodb.org/browse/SERVER-131860) ([CVE-2026-82071](https://www.cve.org/CVERecord?id=CVE-2026-82071) ): Fixed insufficient validation of storage engine configuration options. An authenticated user with write privileges could supply crafted options during collection creation, causing an out-of-bounds memory write and crashing the server process.
- [SERVER-131423](https://jira.mongodb.org/browse/SERVER-131423) ([CVE-2026-82070](https://www.cve.org/CVERecord?id=CVE-2026-82070) ): Fixed inconsistent redaction in the MongoDB Server diagnostic reporting interface. This could expose protected credentials in diagnostic output to an authenticated user.
- [SERVER-131326](https://jira.mongodb.org/browse/SERVER-131326) ([CVE-2026-82068](https://www.cve.org/CVERecord?id=CVE-2026-82068) ): Fixed an issue where crafted retryable write commands containing repeated statement IDs could trigger a fatal assertion. An authenticated user with write privileges could potentially crash the server.
- [SERVER-131420](https://jira.mongodb.org/browse/SERVER-131420) ([CVE-2026-82065](https://www.cve.org/CVERecord?id=CVE-2026-82065) ): Fixed insufficient validation of user-supplied storage configuration options. An authenticated user could persist invalid metadata that prevented the server from operating normally, causing a persistent denial-of-service.
- [SERVER-130759](https://jira.mongodb.org/browse/SERVER-130759) ([CVE-2026-82064](https://www.cve.org/CVERecord?id=CVE-2026-82064) ): Fixed an assertion failure in read concern processing on replica set members. An unauthenticated network client could trigger the failure and cause the server process to terminate.
- [SERVER-131138](https://jira.mongodb.org/browse/SERVER-131138) ([CVE-2026-82062](https://www.cve.org/CVERecord?id=CVE-2026-82062) ): Fixed an authorization issue in the `applyOps` command. An authenticated user with elevated internal privileges could bypass a disabled feature gate and write to internal storage tables, potentially corrupting data or metadata outside the authorized namespace.
- [SERVER-130907](https://jira.mongodb.org/browse/SERVER-130907) ([CVE-2026-82061](https://www.cve.org/CVERecord?id=CVE-2026-82061) ): Fixed a use-after-free issue in query execution memory tracking that could occur when two cursors accessed the same tracked resource. An authenticated user could trigger this condition and terminate the server process, resulting in a denial-of-service.
- [SERVER-130926](https://jira.mongodb.org/browse/SERVER-130926) ([CVE-2026-82058](https://www.cve.org/CVERecord?id=CVE-2026-82058) ): Fixed an issue in JSON Schema validation that could allow an authenticated user with `readWrite` privileges to crash `mongod`. A malformed array field name could trigger an unhandled exception while processing a `$jsonSchema` validation error, resulting in a denial-of-service.
- [SERVER-130495](https://jira.mongodb.org/browse/SERVER-130495) ([CVE-2026-82057](https://www.cve.org/CVERecord?id=CVE-2026-82057) ): Fixed a type confusion issue in WiredTiger storage configuration. An authenticated user with `readWrite` privileges could create a collection with an incompatible configuration value. Subsequent reads from the collection could repeatedly crash `mongod` until an administrator removed or repaired the invalid configuration.
- [SERVER-130202](https://jira.mongodb.org/browse/SERVER-130202) ([CVE-2026-82055](https://www.cve.org/CVERecord?id=CVE-2026-82055) ): Fixed a null pointer dereference during `2dsphere` index key generation. An authenticated user with `write` access could submit a specially crafted GeoJSON document and crash `mongod`.
- [SERVER-130901](https://jira.mongodb.org/browse/SERVER-130901) ([CVE-2026-82054](https://www.cve.org/CVERecord?id=CVE-2026-82054) ): Fixed missing resource limits in the JSON Pointer parser used by `$jsonSchema` query filters. An authenticated user could submit crafted filters that amplified memory consumption and terminated `mongod` through resource exhaustion.
- [SERVER-130785](https://jira.mongodb.org/browse/SERVER-130785) ([CVE-2026-82053](https://www.cve.org/CVERecord?id=CVE-2026-82053) ): Fixed an issue in MongoDB’s LDAP authorization integration where pooled LDAP connections could retain a previously authenticated identity under certain configurations. This could cause authorization checks to run with the wrong LDAP identity and assign roles that did not match the intended access policy. As a result, an authenticated user could receive privileges they were not meant to have.
- [SERVER-127985](https://jira.mongodb.org/browse/SERVER-127985) ([CVE-2026-82052](https://www.cve.org/CVERecord?id=CVE-2026-82052) ): Fixed an issue in the `$regexFindAll` aggregation expression that could cause mongod to crash. Under certain conditions, a regular expression match could begin in the middle of a multi-code-unit character and trigger an assertion during query execution. An authenticated user with permission to run aggregation pipelines could trigger the issue, resulting in a denial of service.

### Medium severity

- [SERVER-132835](https://jira.mongodb.org/browse/SERVER-132835) ([CVE-2026-82069](https://www.cve.org/CVERecord?id=CVE-2026-82069) ): Fixed an issue in query statistics serialization on `mongos` that could expose unredacted query literals. A user with access to query statistics could view sensitive values contained in recorded queries.
- [SERVER-131562](https://jira.mongodb.org/browse/SERVER-131562) ([CVE-2026-82066](https://www.cve.org/CVERecord?id=CVE-2026-82066) ): Fixed a heap out-of-bounds read in the query planning component. A crafted query could cause the server process to read memory beyond the allocated buffer boundaries.
- [SERVER-131870](https://jira.mongodb.org/browse/SERVER-131870) ([CVE-2026-82063](https://www.cve.org/CVERecord?id=CVE-2026-82063) ): Fixed a use-after-free issue in cursor management that could cause the server to crash. Under certain conditions, cursor cleanup could access a resource after its memory had been freed. An authenticated user could trigger this condition, resulting in a denial-of-service attack.
- [SERVER-130571](https://jira.mongodb.org/browse/SERVER-130571) ([CVE-2026-82059](https://www.cve.org/CVERecord?id=CVE-2026-82059) ): Fixed an internal aggregation expression that was incorrectly exposed to external clients. An authenticated user with read-only privileges could invoke it to trigger an assertion failure and cause a denial-of-service.
- [SERVER-130306](https://jira.mongodb.org/browse/SERVER-130306) ([CVE-2026-82056](https://www.cve.org/CVERecord?id=CVE-2026-82056) ): Fixed a race condition in text index query parsing that could cause a heap use-after-free during concurrent text search and index management operations. An authenticated user with `readWrite` privileges could crash the server, causing a denial of service.

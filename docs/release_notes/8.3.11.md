# Percona Server for MongoDB {{ page.meta.version }} ({{date.8_3_11}})

[Installation](../install/index.md){.md-button}
[Upgrade from MongoDB Community](../install/upgrade-from-mongodb.md){.md-button}

!!! warning "Technical Preview"
    Percona Server for MongoDB {{ page.meta.version }} is available as a technical preview.

    We recommend that early adopters use this release for testing purposes only and not in production environments.

We are pleased to announce **Percona Server for MongoDB {{ page.meta.version }}**, the drop-in replacement for MongoDB Community Edition. Percona Server for MongoDB supports MongoDB Community protocols and drivers and enhances it with [enterprise-grade features for free](../comparison.md), helping you meet your organization's requirements for high availability, reliability, and data security.

Percona Server for MongoDB **{{ page.meta.version }}** includes the improvements and bug fixes of:

- [MongoDB 8.3.11 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/8.3/#8311---sept-11-2026){:target="_blank"} and [MongoDB 8.3.9 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/8.3/#839---sept-8-2026){:target="_blank"}.

- Supports protocols and drivers of MongoDB Community **8.3.11**.

## Upgrade recommendation

This release fixes multiple security vulnerabilities inherited from upstream MongoDB. We strongly recommend **upgrading to version {{ page.meta.version }}** as soon as possible.

## Changelog

### Bugs fixed

- [PSMDB-2253](https://perconadev.atlassian.net/browse/PSMDB-2253): Fixed an issue that caused a replica set member to crash during file-copy-based initial sync when KMIP encryption at rest was enabled. The crash occurred when the member started with an empty data directory and no `--kmipKeyIdentifier`. In this case, the member generated a new KMIP master key but could not use it to decrypt the `key.db/` files copied from the sync source.

## Security fixes from upstream MongoDB

The severity categories below follow the upstream [CVSS scores :octicons-link-external-16:](https://nvd.nist.gov/vuln-metrics/cvss){:target="_blank"}, using CVSS 4.0.

### Critical severity

- [SERVER-131229 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131229){:target="_blank"} ([CVE-2026-82067 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82067){:target="_blank"}): Fixed case sensitivity handling in configuration validation that could leave authorization disabled at startup. An unauthenticated user with network access to an affected deployment could perform administrative operations, compromising data confidentiality, integrity, and availability.

### High severity

- [SERVER-134063 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-134063){:target="_blank"} ([CVE-2026-89099 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-89099){:target="_blank"}): Fixed a race condition in the document value layer that could allow concurrent threads to access shared memory without synchronization. An authenticated user with read and write privileges could trigger memory corruption or terminate the server, potentially compromising the confidentiality, integrity, and availability of the server process.

- [SERVER-128253 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-128253){:target="_blank"} ([CVE-2026-82076 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82076){:target="_blank"}): Fixed an integer overflow in query planning that could allow an authenticated user with database read and write privileges to bypass an internal resource limit. A crafted query could exhaust memory and terminate the server, interrupting access to all databases on the affected node.

- [SERVER-132650 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132650){:target="_blank"} ([CVE-2026-82075 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82075){:target="_blank"}): Fixed uncontrolled CPU consumption in `mongos` connection monitoring. An unauthenticated client with access to the router port could submit crafted monitoring parameters and degrade performance or deny service to legitimate clients.

- [SERVER-132125 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132125){:target="_blank"} ([CVE-2026-82073 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82073){:target="_blank"}): Fixed insufficient validation of an internal aggregation parameter when Atlas Search features are in use. An authenticated user with limited read privileges could bypass view authorization checks and read data from collections they were not authorized to access.

- [SERVER-131860 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131860){:target="_blank"} ([CVE-2026-82071 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82071){:target="_blank"}): Fixed insufficient validation of storage engine options during collection creation. An authenticated user with write privileges could supply crafted options that caused an out-of-bounds memory write, crashing the server and potentially allowing arbitrary code execution.

- [SERVER-131423 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131423){:target="_blank"} ([CVE-2026-82070 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82070){:target="_blank"}): Fixed missing credential redaction in diagnostic output for concurrent administrative operations. An authenticated user with monitoring privileges could view cleartext credentials and potentially impersonate other users, including privileged accounts.

- [SERVER-131326 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131326){:target="_blank"} ([CVE-2026-82068 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82068){:target="_blank"}): Fixed an issue where an authenticated user with write privileges could trigger a fatal assertion with crafted retryable write commands. The server could crash repeatedly after restart, and the failure could spread to additional nodes in a sharded cluster. Restoring service required manual intervention.

- [SERVER-131420 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131420){:target="_blank"} ([CVE-2026-82065 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82065){:target="_blank"}): Fixed insufficient validation of storage configuration options supplied during collection creation. An authenticated user with collection creation privileges could persist invalid metadata that crashed the server during diagnostic operations. The metadata survived restarts and replicated to other members, requiring manual intervention to restore service.

- [SERVER-130759 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130759){:target="_blank"} ([CVE-2026-82064 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82064){:target="_blank"}): Fixed an assertion failure in read concern processing that could allow an unauthenticated network client to terminate the server on certain replica set member configurations.

- [SERVER-131138 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131138){:target="_blank"} ([CVE-2026-82062 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82062){:target="_blank"}): Fixed an authorization issue in `applyOps` that could allow an authenticated user with elevated internal privileges to bypass a disabled feature gate. The user could write to internal storage tables outside the checked namespace, including unrelated metadata or collection data.

- [SERVER-130907 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130907){:target="_blank"} ([CVE-2026-82061 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82061){:target="_blank"}): Fixed a use-after-free issue in query execution memory tracking. An authenticated user with read privileges could trigger a write to freed memory through database commands, crashing the server or potentially corrupting memory.

- [SERVER-130926 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130926){:target="_blank"} ([CVE-2026-82058 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82058){:target="_blank"}): Fixed an unhandled exception when generating `$jsonSchema` validation errors. An authenticated user with `readWrite` privileges could submit a document containing a malformed numeric array field name and terminate `mongod`.

- [SERVER-130495 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130495){:target="_blank"} ([CVE-2026-82057 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82057){:target="_blank"}): Fixed a type confusion issue caused by incompatible WiredTiger options supplied during collection creation. An authenticated user with `readWrite` privileges could create a collection that crashed `mongod` when read. The invalid configuration persisted after restarts and required manual intervention.

- [SERVER-130202 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130202){:target="_blank"} ([CVE-2026-82055 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82055){:target="_blank"}): Fixed a null pointer dereference during `2dsphere` index key generation. An authenticated user with write access could insert a crafted GeoJSON document into an indexed collection and crash `mongod`.

- [SERVER-130901 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130901){:target="_blank"} ([CVE-2026-82054 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82054){:target="_blank"}): Fixed insufficient resource limits in the JSON Pointer parser used by `$jsonSchema` query filters. Crafted filters submitted in concurrent requests could exhaust memory and terminate `mongod`, denying service to connected clients.

- [SERVER-130785 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130785){:target="_blank"} ([CVE-2026-82053 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82053){:target="_blank"}): Fixed an LDAP authorization issue where a pooled connection could retain a previously authenticated identity. Under certain configurations, subsequent authorization checks could use the wrong LDAP identity and grant an authenticated user unintended privileges.

- [SERVER-127985 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-127985){:target="_blank"} ([CVE-2026-82052 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82052){:target="_blank"}): Fixed an issue in `$regexFindAll` where a match could start within a multibyte character and trigger an assertion. An authenticated user with permission to run aggregation pipelines could crash `mongod`.

### Medium severity

- [SERVER-132835 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132835){:target="_blank"} ([CVE-2026-82069 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82069){:target="_blank"}): Fixed missing redaction of search query text in query statistics on `mongos`. A user with monitoring privileges could view sensitive query values from other users’ operations.

- [SERVER-131562 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131562){:target="_blank"} ([CVE-2026-82066 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82066){:target="_blank"}): Fixed a heap out-of-bounds read in query planning. An authenticated user with database read and write privileges could submit crafted queries that exposed portions of server memory through diagnostic query statistics.

- [SERVER-131870 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131870){:target="_blank"} ([CVE-2026-82063 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82063){:target="_blank"}): Fixed a use-after-free issue during cursor cleanup. Under specific timing conditions, an authenticated user could cause the server to access freed memory and crash.

- [SERVER-130571 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130571){:target="_blank"} ([CVE-2026-82059 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82059){:target="_blank"}): Fixed an internal aggregation expression that was accessible to external clients. An authenticated user with read-only privileges could submit a malformed index specification and trigger an assertion that terminated `mongod` in certain build configurations.

- [SERVER-130306 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130306){:target="_blank"} ([CVE-2026-82056 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82056){:target="_blank"}): Fixed a race condition in text index query parsing during concurrent text search and index management operations. An authenticated user with `readWrite` privileges could trigger a use-after-free and crash the server.

### Low severity

- [SERVER-131202 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131202){:target="_blank"} ([CVE-2026-82060 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82060){:target="_blank"}): Fixed insufficient validation of shard key values used in change stream lookups. An authenticated user could insert crafted values that were interpreted as query operators when `fullDocument` was set to `updateLookup`. Change stream consumers could receive incorrect post-image documents or encounter non-resumable errors.

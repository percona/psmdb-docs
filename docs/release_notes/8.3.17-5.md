# Percona Server for MongoDB {{ page.meta.version }} ({{date.8_3_17}})

[Installation](../install/index.md){.md-button}
[Upgrade](../install/minor-upgrade.md){.md-button}

Percona Server for MongoDB {{ page.meta.version }} is a drop-in replacement for MongoDB Community Edition. It supports MongoDB Community protocols and drivers and provides [enterprise-grade features at no cost](../comparison.md).

This release includes the improvements and bug fixes from [MongoDB 8.3.16 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/8.3/#8316---nov-10-2026){:target="_blank"} and [MongoDB 8.3.17 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/8.3/#8317---nov-10-2026){:target="_blank"}.

## Upgrade recommendation

This release fixes multiple security vulnerabilities inherited from upstream MongoDB. We strongly recommend **upgrading to version {{ page.meta.version }}** as soon as possible.

See [Upgrade Percona Server for MongoDB](../install/minor-upgrade.md) for upgrade instructions.

## Known issues

- [SERVER-136961 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-136961){:target="_blank"}: If a node has an unclean shutdown and then restarts to perform file copy-based initial sync, it can crash on every restart and cannot complete initial sync without manual intervention. This issue affects Percona Server for MongoDB 8.3.7-1 and later versions. See [File copy-based initial sync known issues](../fcbis.md#known-issues) for recovery steps.

## Changelog

### Bugs fixed

- [PSMDB-2279](https://perconadev.atlassian.net/browse/PSMDB-2279): Fixed AWS IAM authentication for assumed roles in non-commercial AWS partitions, including GovCloud and China. The server now preserves the partition when converting an assumed-role ARN to the IAM role ARN used to match a user in `$external`.

### AWS IAM upgrade considerations

Before upgrading in GovCloud, China, or ISO partitions, review existing `$external` users named with IAM role ARNs. All sessions of the matching role can now authenticate as that user. Users named with full STS assumed-role session ARNs no longer match. Replace these per-session users with appropriately authorized IAM role-ARN users. See [Configure AWS IAM authentication](../aws-iam-setup.md).

## Security fixes from upstream MongoDB

Severity follows the MongoDB-published [CVSS 4.0 scores :octicons-link-external-16:](https://nvd.nist.gov/vuln-metrics/cvss){:target="_blank"}. The macOS and Windows entries apply only to the upstream platforms and configurations described below.

### Critical severity

- [SERVER-138119 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-138119){:target="_blank"}, [SERVER-138175 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-138175){:target="_blank"} ([CVE-2026-118383 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-118383){:target="_blank"}): Fixed a use-after-free when a newly elected replica set primary completes catch-up. Unauthenticated requests could trigger a server crash or, under certain conditions, arbitrary code execution. The issue affects replica set members, including shard and config server members, but not standalone `mongod` instances.

- [SERVER-130681 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130681){:target="_blank"} ([CVE-2026-120808 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120808){:target="_blank"}): Fixed TLS certificate validation for outbound IPv6 connections on macOS with Apple SecureTransport. An attacker on the network path could intercept or modify traffic using a self-signed certificate with the target's IPv6 address in its Subject Alternative Name.

### High severity

- [SERVER-135180 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-135180){:target="_blank"} ([CVE-2026-120803 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120803){:target="_blank"}): Fixed a use-after-free in the slot-based execution (SBE) engine when processing certain `$setWindowFields` aggregation pipelines. An authenticated user with `readWrite` privileges could craft a pipeline that exposes server memory or crashes `mongod`.

- [SERVER-130268 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130268){:target="_blank"} ([CVE-2026-120804 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120804){:target="_blank"}): Fixed a resource leak in Kerberos authentication on Windows Enterprise builds of MongoDB. Repeated requests from an unauthenticated user could exhaust resources and prevent further Kerberos authentication until the server restarts.

- [SERVER-130261 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130261){:target="_blank"} ([CVE-2026-120806 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120806){:target="_blank"}): Fixed stale references left after dropping database roles. A user with database administrative privileges could recreate a role with different privileges, granting them to previously associated users without an explicit grant or audit event.

- [SERVER-130169 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130169){:target="_blank"} ([CVE-2026-120807 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120807){:target="_blank"}): Fixed an X.509 cluster authentication check that could grant internal system privileges to a holder of a valid cluster-member TLS certificate. Exploitation requires a non-default configuration and specific timing and error conditions during user lookup.

- [SERVER-132430 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132430){:target="_blank"} ([CVE-2026-120810 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120810){:target="_blank"}): Fixed missing memory limits for an internal aggregation expression accessible to authenticated clients. A user with read privileges could send crafted commands over concurrent connections, exhausting memory and causing the operating system to terminate `mongod`.

- [SERVER-132517 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132517){:target="_blank"} ([CVE-2026-120813 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120813){:target="_blank"}): Fixed an issue where a malicious client-side field-level encryption (CSFLE) schema could discard encryption metadata and leave fields in plaintext. Exploitation requires control over the schema sent to the client, such as by intercepting network traffic or using an untrusted server.

- [SERVER-133600 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-133600){:target="_blank"} ([CVE-2026-120814 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120814){:target="_blank"}): Fixed a privilege management issue in sharding coordination. A user with certain shard-level administrative privileges and a direct connection to a cluster member could trigger operations with elevated authority, allowing unauthorized data access and changes across the cluster.

- [SERVER-134872 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-134872){:target="_blank"} ([CVE-2026-120815 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120815){:target="_blank"}): Fixed an authorization check that could let an unauthenticated user with local host access gain administrative privileges on a server with authorization enabled. This could expose data and credentials, allow data changes, or disrupt service.

- [SERVER-135655 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-135655){:target="_blank"} ([CVE-2026-120817 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120817){:target="_blank"}): Fixed a race condition during concurrent writes checked against a collection validator with geospatial operators. An authenticated user with write privileges could trigger the issue and crash the server.

- [SERVER-135727 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-135727){:target="_blank"} ([CVE-2026-120818 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120818){:target="_blank"}): Fixed a use-after-free in server-side JavaScript during aggregation. An authenticated user, even without assigned roles, could submit a crafted request that returned unrelated server memory and, in some cases, affected server availability.

- [SERVER-136182 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-136182){:target="_blank"} ([CVE-2026-120822 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120822){:target="_blank"}): Fixed an authorization bypass in a replication-related administrative command. A user with backup and restore privileges could read or relocate collections outside their permitted scope.

- [SERVER-136505 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-136505){:target="_blank"} ([CVE-2026-120824 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120824){:target="_blank"}): Fixed a use-after-free when validating time series bucket documents during writes. An authenticated user with permission to write directly to bucket documents could crash the server or, under certain conditions, execute arbitrary code.

- [SERVER-138119 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-138119){:target="_blank"} ([CVE-2026-120828 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120828){:target="_blank"}): Fixed an issue where an unauthenticated user with network access could send read requests for a point in time that a replica set member would never reach. Internal wait records could accumulate after the requests ended, exhausting server memory and causing a denial-of-service.

### Medium severity

- [SERVER-132279 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132279){:target="_blank"} ([CVE-2026-120809 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120809){:target="_blank"}): Fixed a use-after-free when processing `$unwind` in aggregation pipelines on time series collections. An authenticated user could expose server memory or crash the server when a non-default parameter for the slot-based execution (SBE) engine is enabled.

- [SERVER-135353 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-135353){:target="_blank"} ([CVE-2026-120811 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120811){:target="_blank"}): Fixed a use-after-free in the classic query engine plan cache. Diagnostic commands from an authenticated user could expose server memory or, under certain conditions, crash the server.

- [SERVER-131961 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131961){:target="_blank"} ([CVE-2026-120812 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120812){:target="_blank"}): Fixed uncontrolled recursion during query compilation for time series collections. An authenticated user with read privileges could submit certain queries that exhaust the stack and terminate the server.

- [SERVER-135737 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-135737){:target="_blank"} ([CVE-2026-120820 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-120820){:target="_blank"}): Fixed unbounded memory growth in per-namespace statistics for operations carrying encrypted-field information. A user with read privileges could repeatedly reference arbitrary namespaces, causing memory to remain allocated and slowing the affected code path. Reclaiming the memory required a server restart.

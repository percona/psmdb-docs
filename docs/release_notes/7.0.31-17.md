Percona Server for MongoDB 7.0.31-17 is an enhanced, source-available, and highly-scalable database that is a
fully-compatible, drop-in replacement for MongoDB Community Edition.

Percona Server for MongoDB **7.0.30-17** includes the improvements and bug fixes of: 

- [MongoDB 7.0.31 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/7.0/#7.0.31---mar-17--2026){:target="_blank"}

- [MongoDB 7.0.30 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/7.0/#7.0.30---feb-10--2026){:target="_blank"}
 

It supports protocols and drivers of both MongoDB Community **7.0.30** and MongoDB Community **7.0.31**.


## Release highlights

### Enhanced LDAP authentication caching

To provide better parity with MongoDB Enterprise and improve performance in high-scale environments, we have introduced two new configuration parameters for LDAP user caching. These options allow administrators to fine-tune how and when cached user information is refreshed, reducing unnecessary overhead on LDAP servers while ensuring security data remains current.

**New parameters**

**ldapUserCacheRefreshInterval:** Sets the frequency (in seconds) at which the server proactively refreshes cached user information from the LDAP server. This allows the system to update permissions and group memberships in the background before the cache entry expires. For detailed information see, [MongoDB server parameters](https://www.mongodb.com/docs/manual/reference/parameters/#mongodb-parameter-param.ldapUserCacheRefreshInterval).

**ldapShouldRefreshUserCacheEntries:** A toggle that determines the cache renewal strategy. For detailed information see, [MongoDB server parameters](https://www.mongodb.com/docs/manual/reference/parameters/#mongodb-parameter-param.ldapShouldRefreshUserCacheEntries).


  - If true: The server uses the `ldapUserCacheRefreshInterval` to proactively update entries.

  - If false: The server waits for the `ldapUserCacheInvalidationInterval` (already supported in PSMDB) to pass before clearing and refetching the entry upon the next login attempt.

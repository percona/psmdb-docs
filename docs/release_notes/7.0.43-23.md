# Percona Server for MongoDB {{ page.meta.version }} ({{ date[(release.split('-')[0].replace('.', '') | int)] }})

[Installation](../install/index.md){.md-button}
[Upgrade from MongoDB Community](../install/upgrade-from-mongodb.md){.md-button}

Percona Server for MongoDB {{ page.meta.version }} is an enhanced, source-available, and highly scalable database that is a fully compatible, drop-in replacement for MongoDB Community Edition.

Percona Server for MongoDB **{{ page.meta.version }}** includes the improvements and bug fixes of:

- [MongoDB 7.0.43 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/v7.0/release-notes/7.0/){:target="_blank"}.

- Supports protocols and drivers of MongoDB Community **7.0.43**.

## Upgrade recommendation

This release fixes one critical, twelve high-severity, and four medium-severity vulnerabilities inherited from upstream MongoDB. We strongly recommend upgrading to version {{ page.meta.version }} as soon as possible.

## Security fixes from upstream MongoDB

This release fixes vulnerabilities inherited from upstream MongoDB. The severity categories below follow the upstream [CVSS scores :octicons-link-external-16:](https://nvd.nist.gov/vuln-metrics/cvss){:target="_blank"}.

### Critical severity

- [SERVER-131229 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131229){:target="_blank"} ([CVE-2026-82067 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82067){:target="_blank"}): Fixed an issue in MongoDB Server's configuration validation where incorrect handling of case sensitivity could leave authorization disabled during startup. If this occurred, an unauthenticated user with network access could perform administrative operations without authorization, potentially compromising data confidentiality, integrity, and availability.

### High severity

- [SERVER-134063 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-134063){:target="_blank"} ([CVE-2026-89099 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-89099){:target="_blank"}): Fixed a race condition in the document value layer of MongoDB Server that allowed concurrent server threads to operate on the same internal memory without synchronization, leading to memory corruption. An authenticated user with read-write privileges could trigger this condition over the normal client protocol. This could result in server termination and potential corruption of process memory with user-influenced content.  This vulnerability could compromise the confidentiality, integrity, and availability of the affected server process.

- [SERVER-128253 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-128253){:target="_blank"} ([CVE-2026-82076 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82076){:target="_blank"}): Fixed an integer overflow in the query planning component of MongoDB Server that allowed an authenticated user with ordinary database-level read/write privileges to bypass an internal resource limit. Submitting a specially crafted query caused the server to consume memory without bound during query planning, which exhausted the server process and caused a denial-of-service affecting all databases served by the affected node.

- [SERVER-132650 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132650){:target="_blank"} ([CVE-2026-82075 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82075){:target="_blank"}): 
Fixed an uncontrolled resource consumption in the request-handling path of the MongoDB sharded-cluster router process. An unauthenticated client with network access to a router port could supply connection-monitoring parameters that caused the server to expend CPU resources without any rate limiting, degradation, or denial of service to legitimate clients.

- [SERVER-132275 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132275){:target="_blank"} ([CVE-2026-82074 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82074){:target="_blank"}): Fixed an authorization issue in the aggregation framework where `$lookup` accepted multiple `pipeline` arguments. This could allow an authenticated user to read collection data without the required authorization.

- [SERVER-131423 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131423){:target="_blank"} ([CVE-2026-82070 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82070){:target="_blank"}): Fixed inconsistent redaction in the MongoDB Server diagnostic reporting interface. This could expose protected credentials in diagnostic output to an authenticated user.

- [SERVER-131326 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131326){:target="_blank"} ([CVE-2026-82068 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82068){:target="_blank"}): Fixed an issue where crafted retryable write commands containing repeated statement IDs could trigger a fatal assertion. An authenticated user with write privileges could potentially crash the server.

- [SERVER-131420 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131420){:target="_blank"} ([CVE-2026-82065 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82065){:target="_blank"}): Fixed insufficient validation of user-supplied storage configuration options. An authenticated user could persist invalid metadata that prevented the server from operating normally, causing a persistent denial-of-service.

- [SERVER-130759 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130759){:target="_blank"} ([CVE-2026-82064 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82064){:target="_blank"}): Fixed an assertion failure in read concern processing on replica set members. An unauthenticated network client could trigger the failure and cause the server process to terminate.

- [SERVER-130926 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130926){:target="_blank"} ([CVE-2026-82058 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82058){:target="_blank"}): Fixed an issue in JSON Schema validation that could allow an authenticated user with `readWrite` privileges to crash `mongod`. A malformed array field name could trigger an unhandled exception while processing a `$jsonSchema` validation error, resulting in a denial-of-service.

- [SERVER-130901 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130901){:target="_blank"} ([CVE-2026-82054 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82054){:target="_blank"}): Fixed missing resource limits in the JSON Pointer parser used by `$jsonSchema` query filters. An authenticated user could submit crafted filters that amplified memory consumption and terminated `mongod` through resource exhaustion.

- [SERVER-130785 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130785){:target="_blank"} ([CVE-2026-82053 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82053){:target="_blank"}): Fixed an issue in MongoDB's LDAP authorization integration where pooled LDAP connections could retain a previously authenticated identity under certain configurations. This could cause authorization checks to run with the wrong LDAP identity and assign roles that did not match the intended access policy. As a result, an authenticated user could receive privileges they were not meant to have.

- [SERVER-124077 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-124077){:target="_blank"} ([CVE-2026-82052 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82052){:target="_blank"}): Fixed an issue in the `$regexFindAll `aggregation expression that could cause mongod to crash. Under certain conditions, a regular expression match could begin in the middle of a multi-code-unit character and trigger an assertion during query execution. An authenticated user with permission to run aggregation pipelines could trigger the issue, resulting in a denial of service.

### Medium severity

- [SERVER-131562 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131562){:target="_blank"} ([CVE-2026-82066 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82066){:target="_blank"}): Fixed a heap out-of-bounds read in the query planning component. A crafted query could cause the server process to read memory beyond the allocated buffer boundaries.

- [SERVER-131870 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131870){:target="_blank"} ([CVE-2026-82063 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82063){:target="_blank"}): Fixed a use-after-free issue in cursor management that could cause the server to crash. Under certain conditions, cursor cleanup could access a resource after its memory had been freed. An authenticated user could trigger this condition, resulting in a denial-of-service attack.

- [SERVER-130571 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130571){:target="_blank"} ([CVE-2026-82059 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82059){:target="_blank"}): Fixed an internal aggregation expression that was incorrectly exposed to external clients. An authenticated user with read-only privileges could invoke it to trigger an assertion failure and cause a denial-of-service.

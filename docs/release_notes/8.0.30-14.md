# Percona Server for MongoDB {{ page.meta.version }} ({{date.[8_0_30]}})

[Installation](../install/index.md){.md-button}
[Upgrade from MongoDB Community](../install/upgrade-from-mongodb.md){.md-button}

Percona Server for MongoDB {{ page.meta.version }} is an enhanced, source-available, and highly scalable database that is a fully compatible, drop-in replacement for MongoDB Community Edition.

Percona Server for MongoDB **{{ page.meta.version }}** includes the improvements and bug fixes of:

- [MongoDB 8.0.30 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/8.0#8030---sept-8-2026){:target="_blank"}.

- Supports protocols and drivers of MongoDB Community **8.0.30**.

## Upgrade recommendation

This release fixes one critical and 11 high-severity vulnerabilities affecting earlier Percona Server for MongoDB 8.0.x versions. We strongly recommend upgrading to version {{ page.meta.version }} as soon as possible.

## Security fixes from upstream MongoDB

This release fixes vulnerabilities inherited from upstream MongoDB. The severity categories below follow the upstream [CVSS scores :octicons-link-external-16:](https://nvd.nist.gov/vuln-metrics/cvss){:target="_blank"}.

### Critical severity

- [SERVER-131229 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131229){:target="_blank"} ([CVE-2026-82067 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82067){:target="_blank"}): Fixed an issue in configuration validation where case-insensitive option handling could leave authorization disabled during server startup. Under affected configurations, an unauthenticated user with network access could perform administrative operations and compromise data confidentiality, integrity, and availability.

### High severity

- [SERVER-130901 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130901){:target="_blank"} ([CVE-2026-82054 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82054){:target="_blank"}): Fixed an issue in the JSON Pointer parser used by `$jsonSchema` query filters where an authenticated user could submit specially crafted input that caused excessive memory allocation. Concurrent requests could exhaust available memory and terminate `mongod`, resulting in a denial-of-service.

- [SERVER-130785 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130785){:target="_blank"} ([CVE-2026-82053 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82053){:target="_blank"}): Fixed an issue in LDAP authorization where pooled connections could retain a stale authenticated identity. Under certain configurations, authorization queries could run under the wrong LDAP identity and assign an authenticated user privileges not intended by the deployment's access policy.

- [SERVER-128253 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-128253){:target="_blank"} ([CVE-2026-82076 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82076){:target="_blank"}): Fixed an integer overflow in the query planner where an authenticated user with database read and write privileges could bypass an internal resource limit. A specially crafted query could cause unbounded memory consumption and terminate `mongod`, resulting in a denial-of-service.

- [SERVER-132650 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132650){:target="_blank"} ([CVE-2026-82075 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82075){:target="_blank"}): Fixed an issue in the sharded-cluster router where an unauthenticated client with network access to a `mongos` port could supply connection-monitoring parameters that consumed CPU without rate limiting. This could degrade or deny service to legitimate clients.

- [SERVER-132275 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132275){:target="_blank"} ([CVE-2026-82074 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82074){:target="_blank"}): Fixed an authorization issue in the aggregation framework where an authenticated user with minimal privileges could submit a specially formatted request that caused the authorization check to evaluate a different operation from the one executed. This could expose collection data within the target database without the required permissions.

- [SERVER-131423 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131423){:target="_blank"} ([CVE-2026-82070 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82070){:target="_blank"}): Fixed an issue in the diagnostic reporting interface where an authenticated user with monitoring privileges could view credentials from concurrent administrative operations without proper redaction. Exposed credentials could allow the user to impersonate another account, including a privileged account.

- [SERVER-131326 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131326){:target="_blank"} ([CVE-2026-82068 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82068){:target="_blank"}): Fixed an issue where an authenticated user with write privileges could submit specially crafted retryable write commands that caused a persistent fatal assertion. The resulting crash state could survive restarts and propagate to other nodes in a sharded cluster, requiring manual intervention to restore service.

- [SERVER-131420 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131420){:target="_blank"} ([CVE-2026-82065 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82065){:target="_blank"}): Fixed an issue in storage engine configuration validation where an authenticated user with collection creation privileges could persist invalid options in collection metadata. Reading the affected metadata could trigger a fatal assertion, and the invalid state could survive restarts and replicate to other cluster members, causing a persistent denial-of-service.

- [SERVER-130759 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130759){:target="_blank"} ([CVE-2026-82064 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82064){:target="_blank"}): Fixed an issue in read concern processing where an unauthenticated user could trigger an invalid assertion on certain replica set member configurations. This could terminate the server process and cause a denial-of-service.

- [SERVER-124077 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-124077){:target="_blank"} ([CVE-2026-82052 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82052){:target="_blank"}): Fixed an issue in the `$regexFindAll` aggregation expression where an authenticated user could make a regular expression match begin inside a multibyte UTF-8 character. This could trigger an assertion and terminate `mongod`, resulting in a denial-of-service.

- [SERVER-130926 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130926){:target="_blank"} ([CVE-2026-82058 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82058){:target="_blank"}): Fixed an issue in `$jsonSchema` validation error generation where an authenticated user with `readWrite` privileges could submit an array containing a malformed numeric field name. Unsafe conversion of that field name could raise an unhandled exception and terminate `mongod`, resulting in a denial-of-service.

### Medium severity

- [SERVER-130306 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130306){:target="_blank"} ([CVE-2026-82056 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82056){:target="_blank"}): Fixed a race condition in text index query parsing where an authenticated user with `readWrite` privileges could trigger a heap use-after-free during concurrent text-search and index management operations. This could crash the server and cause a denial-of-service.

- [SERVER-131562 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131562){:target="_blank"} ([CVE-2026-82066 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82066){:target="_blank"}): Fixed an out-of-bounds memory read in the query planner where an authenticated user with database read and write privileges could submit crafted queries that read beyond an allocated buffer. A limited amount of process memory could be exposed through diagnostic query statistics.

- [SERVER-131870 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131870){:target="_blank"} ([CVE-2026-82063 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82063){:target="_blank"}): Fixed a use-after-free in cursor management where an authenticated user could, under specific timing conditions, cause cursor cleanup to dereference a freed resource. This could crash the server and cause a denial-of-service.

- [SERVER-130571 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130571){:target="_blank"} ([CVE-2026-82059 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82059){:target="_blank"}): Fixed an issue where an internal aggregation expression was available to authenticated users. A user with read privileges could supply a malformed index specification that triggered an assertion and, in certain builds, terminated `mongod`, resulting in a denial-of-service.

### Low severity

- [SERVER-131202 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131202){:target="_blank"} ([CVE-2026-82060 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82060){:target="_blank"}): Fixed an issue in sharded collections where an authenticated user could insert operator-shaped objects as shard key values. When processed by a change stream using `updateLookup`, these values could be interpreted as query operators, causing consumers to receive incorrect post-image documents or encounter non-resumable errors.

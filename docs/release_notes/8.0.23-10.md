## Security updates: CVE fixes from upstream MongoDB

This release includes upstream MongoDB security fixes for the following vulnerabilities:

### High severity

- [SERVER-126021 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-126021){:target="_blank"} **(CVE-2026-8053)**: Fixed an issue in MongoDB Server's time-series collection implementation that allowed an authenticated user with database write privileges to trigger an out-of-bounds memory write in the mongod process. The issue resulted from an inconsistency in the internal `field-name-to-index` mapping within the time-series bucket catalog. Under certain conditions, this resulted in arbitrary code execution. 

- [SERVER-122449 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-122449){:target="_blank"} **(CVE-2026-8199)**: We fixed an issue where authenticated users could trigger excessive memory consumption using specific bitwise operators (`$bitsAllSet, $bitsAnySet, $bitsAllClear`, and `$bitsAnyClear`). This occurred during the processing of the Abstract Syntax Tree (AST) and could lead to system instability or service unavailability due to out-of-memory (OOM) errors.

- [SERVER-121610 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-121610){:target="_blank"} **(CVE-2026-8336)**: A vulnerability was identified in MongoDB Server where invoking `$_internalJsEmit` (an internal function not intended for direct use) or crafting a `mapreduce` command’s map function in a certain way could destabilize the server. When combined with subsequent use of the server-side JavaScript engine (via `$where, $function`, or the `mapreduce` reduce stage), an authenticated user could trigger a crash in the mongod process. The issue has been resolved now.

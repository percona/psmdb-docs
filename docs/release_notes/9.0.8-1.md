# Percona Server for MongoDB {{ page.meta.version }} ({{date.9_0_8}})

[Installation](../install/index.md){.md-button}
[Upgrade](https://www.mongodb.com/docs/manual/release-notes/9.0-upgrade-standalone/){.md-button}

Percona Server for MongoDB {{ page.meta.version }} is the first release in the 9.0 series. It's based on [MongoDB 9.0.8 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/#908---nov-10-2026){:target="_blank"}, so it brings in the upstream 9.0 features along with every fix released through 9.0.8. That includes fixes for 25 security vulnerabilities, one of them rated critical.

Percona-specific changes in this release focus on LDAP and Percona Memory Engine. The server now caches LDAP user-to-DN mappings, which cuts down on repeated directory lookups during login. Percona Memory Engine also handles WiredTiger settings differently, so check your configuration before you upgrade.

## Upgrade considerations

Before you upgrade, read the [MongoDB 9.0 compatibility changes :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/){:target="_blank"} and make sure your drivers support 9.0. Then check the following Percona-specific changes.

### `createBackup` command removed

The `createBackup` command was deprecated in 8.3.17-5 and no longer exists in 9.0. If your scripts still call it, move them to [Percona Backup for MongoDB :octicons-link-external-16:](https://docs.percona.com/percona-backup-mongodb/latest/installation.html){:target="_blank"} before you upgrade.

### Percona Memory Engine settings

Percona Memory Engine now uses more of your WiredTiger settings. Compression options under `storage.wiredTiger`, such as `blockCompressor`, `zstdCompressionLevel`, and `prefixCompression`, now apply to Percona Memory Engine too. Earlier versions ignored them. If your configuration file still has a `storage.wiredTiger` section, review it before you switch over. See [Percona Memory Engine configuration](#percona-memory-engine-configuration).

### AWS IAM role users outside the commercial partition

This change affects MONGODB-AWS authentication in AWS GovCloud, China, and other non-commercial partitions. Assumed-role sessions now authenticate as the `$external` user named after the IAM role ARN, the same way they already do in commercial regions. This has two side effects:

* Every session of a role can now use an existing role ARN user, such as `arn:aws-us-gov:iam::<account_id>:role/<role_name>`. Check the privileges of these users before you upgrade.
* If you worked around the bug by creating users with a full STS session ARN, those users no longer match and their logins fail. Replace them with role ARN users.

See [Configure AWS IAM authentication](../aws-iam-setup.md) for the user format.

## Release highlights

### LDAP user-to-DN caching and monitoring

Each LDAP login maps the username to a distinguished name (DN). When your `ldapUserToDNMapping` rules use an LDAP query, that means an extra directory search on every login. Percona Server for MongoDB now caches these mappings, so repeat logins can skip the search.

Two server parameters control the cache. `ldapUserToDNCacheTTLSeconds` sets how long an entry stays valid (default: 30 seconds), and `ldapUserToDNCacheSize` caps the number of entries (default: 10,000). Set either one to `0` to turn the cache off. You can change both at startup or at runtime, and changing either one clears the cache:

```javascript
db.adminCommand({ setParameter: 1, ldapUserToDNCacheTTLSeconds: 60 })
```

To see how well the cache is working, check the new `ldap.userToDNCache` section in `serverStatus`:

```javascript
db.serverStatus().ldap.userToDNCache
```

The output shows whether the cache is enabled, its configured and current size, the TTL, and counters for hits, misses, and invalidations. The hit and miss counters reset whenever the cache is cleared, so read them alongside `invalidations`. See [LDAP configuration parameters](../ldap-parameters.md) for field details and a hit-rate example.

### Percona Memory Engine configuration

Percona Memory Engine now inherits your `storage.wiredTiger` settings, with a few exceptions. Memory size, the statistics logging interval, and custom configuration strings always come from `storage.inMemory`. If you leave one of those out, the engine uses its own default rather than the WiredTiger value.

The compression settings carry over. These include the collection block compressor, the Zstandard compression level, and index prefix compression. Settings tied to journaling, checkpoints, and live restore don't apply to an in-memory engine, so Percona Memory Engine ignores them.

For the full list of inherited, replaced, and ignored settings, see [How WiredTiger settings apply](../inmemory.md#how-wiredtiger-settings-apply).

## Upstream improvements

Here are some of the MongoDB 9.0 changes you're most likely to notice. For everything else, see [Release Notes for MongoDB 9.0 :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/){:target="_blank"}.

### Resource management

A single query operation now has a memory cap. By default, it's 1 GB or 20% of the memory available to the server process, whichever is greater. Queries that go over it fail with an `ExceededMemoryLimit` error. You can adjust the cap with `internalQueryMaxMemoryUsageBytesPerOperation`. The existing 100 MB per-stage limit and spill-to-disk behavior stay the same. See [Aggregation pipeline limits :octicons-link-external-16:](https://www.mongodb.com/docs/manual/core/aggregation-pipeline-limits/){:target="_blank"}.

The server also limits how many multi-document transactions external clients can keep open at once. The default is 10,000, and you can change it with `maxConcurrentMultiDocumentTransactions`. Once the limit is reached, new transactions fail with a `TooManyOpenTransactions` error.

### Query controls and diagnostics

You can now pass `querySettings` directly to a `find`, `distinct`, or `aggregate` command. These settings apply to that one execution and aren't stored on the cluster. If cluster query settings already exist for the same query shape and both set the same field, the cluster setting wins. With feature compatibility version (FCV) 9.0, you can also set `maxTimeMS` for a query shape with `setQuerySettings`. See [Query settings :octicons-link-external-16:](https://www.mongodb.com/docs/manual/reference/command/setquerysettings/){:target="_blank"}.

Monitoring gets more detail too:

* `serverStatus` reports query memory usage and change stream cursor activity.
* Query statistics now cover `insert`, `update`, and `delete` commands.
* During logical initial sync, `replSetGetStatus` shows the current phase, transfer rate, and attempt history.

### Server-side JavaScript

`$accumulator`, `$function`, and `$where` are no longer deprecated. They now run on a WebAssembly-based JavaScript engine with stronger isolation.

One side effect to watch for: the new engine evaluates local `Date` operations in UTC, whatever the host time zone is. Code that calls methods such as `getHours()` can return different results after the upgrade. Review the [JavaScript compatibility changes :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/){:target="_blank"} before you upgrade.

### Time series collections and document validation

Time series collections are now stored as a single namespace, and you can rename them with `renameCollection`. If a database holds more than 5,000 time series collections, expect the upgrade to take longer and to see some write latency spikes.

The new `constraint` validation level applies your validation rules to every insert and update and guarantees that every document in the collection satisfies them, including documents that were already there. See [Validation levels :octicons-link-external-16:](https://www.mongodb.com/docs/manual/core/schema-validation/specify-validation-level/){:target="_blank"}.

### Notable upstream fixes

* [SERVER-134533](https://jira.mongodb.org/browse/SERVER-134533): Prevents metadata inconsistencies when shard draining starts during `movePrimary`.

* [SERVER-133518](https://jira.mongodb.org/browse/SERVER-133518): Fixes a hang during step-up that blocked a shard from becoming primary after an interrupted chunk operation.

* [SERVER-127745](https://jira.mongodb.org/browse/SERVER-127745): Prevents a resharding deadlock after a quick step-down and step-up of the primary.

* [SERVER-114507](https://jira.mongodb.org/browse/SERVER-114507): Makes `$out` recreate an unsharded output collection on the shard where it already lived, instead of moving it to the primary shard.

* [SERVER-134723](https://jira.mongodb.org/browse/SERVER-134723): Prevents a crash when a newly elected primary can't find a sync source for catch-up.

* [SERVER-135249](https://jira.mongodb.org/browse/SERVER-135249): Stops change stream metric errors from blocking `serverStatus`.

For the complete list, see the [MongoDB 9.0 changelog :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-changelog/){:target="_blank"}.

## Security fixes from upstream MongoDB

MongoDB 9.0.8 carries every security fix from the earlier 9.0 patch releases. The following ones apply to Percona Server for MongoDB. Severity levels follow MongoDB's CVSS 4.0 ratings.

### Critical severity

* [SERVER-138119](https://jira.mongodb.org/browse/SERVER-138119), [SERVER-138175](https://jira.mongodb.org/browse/SERVER-138175) ([CVE-2026-118383](https://www.cve.org/CVERecord?id=CVE-2026-118383)): Fixes a memory error during primary catch-up in replica sets. An unauthenticated attacker could use it to take down replica set members and possibly run arbitrary code. Standalone servers aren't affected.

### High severity

* [SERVER-130431](https://jira.mongodb.org/browse/SERVER-130431) ([CVE-2026-96299](https://www.cve.org/CVERecord?id=CVE-2026-96299)): Adds a missing authorization check to an internal aggregation stage. Without it, an authenticated user with read and write privileges could crash `mongos`.

* [SERVER-131412](https://jira.mongodb.org/browse/SERVER-131412) ([CVE-2026-104004](https://www.cve.org/CVERecord?id=CVE-2026-104004)): Fixes collection validators that could crash the server when an authenticated user inserted a document.

* [SERVER-131411](https://jira.mongodb.org/browse/SERVER-131411) ([CVE-2026-104005](https://www.cve.org/CVERecord?id=CVE-2026-104005)): Fixes authorization for bulk writes routed through `mongos`. An authenticated user with write access to a regular collection could send a bulk write to an internal system namespace they weren't authorized to write to, and the router would accept it.

* [SERVER-135180](https://jira.mongodb.org/browse/SERVER-135180) ([CVE-2026-120803](https://www.cve.org/CVERecord?id=CVE-2026-120803)): Fixes a memory error in the `$locf` window operator. An authenticated user with read and write privileges could use it to expose server memory or crash `mongod`.

* [SERVER-130169](https://jira.mongodb.org/browse/SERVER-130169) ([CVE-2026-120807](https://www.cve.org/CVERecord?id=CVE-2026-120807)): Fixes an X.509 cluster membership check that could grant internal privileges. Exploiting it required a valid cluster member certificate, specific user lookup conditions, and a non-default cluster authentication setup.

## Known issues

These upstream issues are still open in MongoDB 9.0.8:

* [SERVER-136226](https://jira.mongodb.org/browse/SERVER-136226): Each node opens at least `ShardingTaskExecutorPoolMinSize` connections to every config server, which can exhaust config server connections. If you run dedicated config servers and `ShardingTaskExecutorPoolMinSize` is greater than `1`, set `ShardingTaskExecutorPoolMinSizeForConfigServers` to `1` before you upgrade.

* [SERVER-89953](https://jira.mongodb.org/browse/SERVER-89953): At FCV 9.0, `listIndexes` shows the simple collation explicitly. Some object-document mappers (ODMs) read that as a change and drop and rebuild indexes that haven't changed. Don't sync indexes automatically when your application starts. Instead, review the index differences and apply them as a separate deployment step. If you use Mongoose, upgrade to 9.10.4 or 8.24.5.

* [SERVER-136961](https://jira.mongodb.org/browse/SERVER-136961): After an unclean shutdown, a node set up for file copy based initial sync can crash on restart. To recover, restart the node with `initialSyncMethod` set to `logical`.

Check [MongoDB 9.0 known issues :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/#known-issues){:target="_blank"} for updates.

## Changelog

### New features

* [PSMDB-2003](https://perconadev.atlassian.net/browse/PSMDB-2003): Caches LDAP user-to-DN mappings to reduce LDAP lookups during authentication. You can tune the cache with `ldapUserToDNCacheTTLSeconds` and `ldapUserToDNCacheSize`.

### Improvements

* [PSMDB-1832](https://perconadev.atlassian.net/browse/PSMDB-1832): Percona Memory Engine now inherits `storage.wiredTiger` settings, except the ones that `storage.inMemory` options replace. See [Percona Memory Engine](../inmemory.md).

* [PSMDB-2038](https://perconadev.atlassian.net/browse/PSMDB-2038): Adds LDAP user-to-DN cache metrics to `serverStatus` under `ldap.userToDNCache`.

* [PSMDB-2150](https://perconadev.atlassian.net/browse/PSMDB-2150), [PSMDB-2257](https://perconadev.atlassian.net/browse/PSMDB-2257): Binary packages, Docker images, and tarballs now include a [software bill of materials (SBOM)](../sbom.md).

### Removed features

* [PSMDB-2291](https://perconadev.atlassian.net/browse/PSMDB-2291): Removes the `createBackup` command. Use Percona Backup for MongoDB instead.

### Fixed bugs

* [PSMDB-1766](https://perconadev.atlassian.net/browse/PSMDB-1766): Fixes LDAP user cache invalidation. The server didn't clear cached `$external` users at the `ldapUserCacheInvalidationInterval`, so role changes in LDAP weren't picked up. See [LDAP cache refresh parameters](../authorization.md#ldap-cache-refresh-parameters).

* [PSMDB-1937](https://perconadev.atlassian.net/browse/PSMDB-1937): You can now build Percona Server for MongoDB from source in a directory that isn't a Git repository.

* [PSMDB-2200](https://perconadev.atlassian.net/browse/PSMDB-2200): Fixes duplicate symbol errors when building with the mold linker.

* [PSMDB-2279](https://perconadev.atlassian.net/browse/PSMDB-2279): Fixes MONGODB-AWS authentication for assumed roles in AWS GovCloud, China, and other non-commercial partitions. The server now keeps the ARN's partition when it maps an assumed-role session to its IAM role.

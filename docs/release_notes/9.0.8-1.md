# Percona Server for MongoDB {{ page.meta.version }} ({{date.9_0_8}})

[Installation](../install/index.md){.md-button}
[Upgrade](https://www.mongodb.com/docs/manual/release-notes/9.0-upgrade-standalone/){.md-button}

Percona Server for MongoDB {{ page.meta.version }} is the first release in the 9.0 series. It adds LDAP mapping cache controls and metrics. It also changes how Percona Memory Engine reads WiredTiger settings.

This release incorporates [MongoDB 9.0.8 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/#908---nov-10-2026){:target="_blank"}. The release includes upstream features and fixes through MongoDB 9.0.8. See the [MongoDB 9.0 changelog :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-changelog/){:target="_blank"} for upstream release details.

## Upgrade considerations

Review the [MongoDB 9.0 compatibility changes :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/){:target="_blank"} and confirm driver compatibility before upgrading.

The `createBackup` command is unavailable in 9.0. Migrate scripts that use this command to [Percona Backup for MongoDB :octicons-link-external-16:](https://docs.percona.com/percona-backup-mongodb/latest/installation.html){:target="_blank"}.

For Percona Memory Engine, review the [inherited WiredTiger settings](#percona-memory-engine-configuration), especially compression options.

In AWS GovCloud, China, or ISO deployments, review permissions before replacing STS session ARN users with IAM role ARN users. Sessions for the same role authenticate as the same database user. See [Configure AWS IAM authentication](../aws-iam-setup.md).

## Release highlights

### LDAP user-to-DN caching and monitoring

Percona Server for MongoDB caches LDAP user-to-DN mappings to reduce repeated directory searches. Set the entry lifetime with `ldapUserToDNCacheTTLSeconds` (default: 30 seconds). Set the maximum number of entries with `ldapUserToDNCacheSize` (default: 10,000). Set either parameter to `0` to disable the cache.

The `ldap.userToDNCache` section in `serverStatus` reports cache usage, hits, misses, and invalidations. Use these metrics to assess cache capacity for your workload. See [LDAP configuration parameters](../ldap-parameters.md).

### Percona Memory Engine configuration

Percona Memory Engine inherits `storage.wiredTiger` settings unless the corresponding `storage.inMemory` options override those settings. These overrides cover memory size, statistics log intervals, and custom configuration strings. The engine preserves compression settings, including the block compressor, Zstandard compression level, and index prefix compression. Journaling and live restore settings have no effect on Percona Memory Engine. See [Percona Memory Engine](../inmemory.md) for configuration guidance.

### Upstream improvements

#### Resource management

MongoDB 9.0 limits the memory a single query operation can use. The default limit is the greater of 1 GB or 20% of available process memory. Per-stage limits and spill-to-disk behavior still apply. See [Aggregation pipeline limits :octicons-link-external-16:](https://www.mongodb.com/docs/manual/core/aggregation-pipeline-limits/){:target="_blank"}.

The server allows up to 10,000 concurrently open multi-document transactions from external clients by default. Set the limit with `maxConcurrentMultiDocumentTransactions`.

#### Query controls and diagnostics

Use command-level `querySettings` on `find`, `distinct`, or `aggregate` to tune a single execution. Cluster settings take precedence when both sources specify the same field. At feature compatibility version (FCV) 9.0, set `maxTimeMS` for a query shape. See [Query settings :octicons-link-external-16:](https://www.mongodb.com/docs/manual/reference/command/setquerysettings/){:target="_blank"}.

Additional `serverStatus` metrics report query memory usage and change stream activity. MongoDB 9.0 query statistics also cover `insert`, `update`, and `delete` commands. Logical initial sync reports its phase, transfer rate, and attempt history through `replSetGetStatus`.

#### Server-side JavaScript

The `$accumulator`, `$function`, and `$where` operators are no longer deprecated. These operators use a WebAssembly-based JavaScript engine with stronger isolation. Review [JavaScript compatibility changes :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/){:target="_blank"} before the upgrade.

#### Time series collections and document validation

Time series collections use a single namespace. You can rename time series collections with `renameCollection`. The `constraint` validation level requires every document to satisfy the collection's validation rules. These rules also apply to existing documents. See [Validation levels :octicons-link-external-16:](https://www.mongodb.com/docs/manual/core/schema-validation/specify-validation-level/){:target="_blank"}.

For the full feature list, see [Release Notes for MongoDB 9.0 :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/){:target="_blank"} and [Compatibility Changes in MongoDB 9.0 :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/){:target="_blank"}.

#### Notable upstream fixes

* [SERVER-134533](https://jira.mongodb.org/browse/SERVER-134533): Prevents metadata inconsistencies when shard draining starts during `movePrimary`.

* [SERVER-133518](https://jira.mongodb.org/browse/SERVER-133518): Resolves a step-up hang after an interrupted chunk operation. The hang prevents the shard from becoming primary.

* [SERVER-127745](https://jira.mongodb.org/browse/SERVER-127745): Prevents a resharding deadlock after a rapid primary step-down and step-up.

* [SERVER-114507](https://jira.mongodb.org/browse/SERVER-114507): Prevents `$out` from unexpectedly relocating an unsharded output collection to the primary shard.

* [SERVER-134723](https://jira.mongodb.org/browse/SERVER-134723): Prevents a crash when an elected primary cannot find a synchronization source for catch-up.

* [SERVER-135249](https://jira.mongodb.org/browse/SERVER-135249): Fixes change stream metric errors that can interrupt `serverStatus`.

* [SERVER-138547](https://jira.mongodb.org/browse/SERVER-138547): Uses the target architecture in directory names inside cross-compiled archives.

## Security fixes from upstream MongoDB

MongoDB 9.0.8 includes the security fixes from earlier 9.0 releases. The following fixes apply to Percona Server for MongoDB. Severity categories use MongoDB's CVSS 4.0 ratings.

### Critical severity

* [SERVER-138119](https://jira.mongodb.org/browse/SERVER-138119), [SERVER-138175](https://jira.mongodb.org/browse/SERVER-138175) ([CVE-2026-118383](https://www.cve.org/CVERecord?id=CVE-2026-118383)): Fixes a replication memory error during primary catch-up. Unauthenticated requests can exploit the vulnerability to terminate replica set members. Exploitation can also permit arbitrary code execution. Standalone servers are not affected.

### High severity

* [SERVER-130431](https://jira.mongodb.org/browse/SERVER-130431) ([CVE-2026-96299](https://www.cve.org/CVERecord?id=CVE-2026-96299)): Fixes an aggregation authorization issue. Authenticated users with read and write privileges can exploit the vulnerability to crash `mongos`.

* [SERVER-131412](https://jira.mongodb.org/browse/SERVER-131412) ([CVE-2026-104004](https://www.cve.org/CVERecord?id=CVE-2026-104004)): Fixes collection validation expressions that can terminate the server when an authenticated user inserts a document.

* [SERVER-131411](https://jira.mongodb.org/browse/SERVER-131411) ([CVE-2026-104005](https://www.cve.org/CVERecord?id=CVE-2026-104005)): Fixes an authorization issue in an internal aggregation stage. Authenticated users with read and write privileges can exploit the vulnerability to terminate `mongos`.

* [SERVER-135180](https://jira.mongodb.org/browse/SERVER-135180) ([CVE-2026-120803](https://www.cve.org/CVERecord?id=CVE-2026-120803)): Fixes a `$locf` window aggregation memory error that can expose server memory. The vulnerability can also crash `mongod`. Exploitation requires authentication and read and write privileges.

* [SERVER-130261](https://jira.mongodb.org/browse/SERVER-130261) ([CVE-2026-120806](https://www.cve.org/CVERecord?id=CVE-2026-120806)): Fixes incomplete cleanup when administrators drop roles. The vulnerability permits unintended privilege inheritance when administrators recreate a role with the same name.

* [SERVER-130169](https://jira.mongodb.org/browse/SERVER-130169) ([CVE-2026-120807](https://www.cve.org/CVERecord?id=CVE-2026-120807)): Fixes an X.509 authentication check that can grant internal privileges. Exploitation requires a valid cluster-member certificate, specific user-lookup conditions, and a non-default cluster authentication configuration.

* [SERVER-132430](https://jira.mongodb.org/browse/SERVER-132430) ([CVE-2026-120810](https://www.cve.org/CVERecord?id=CVE-2026-120810)): Limits memory use in an aggregation expression. The vulnerability permits authenticated users with read privileges to exhaust server memory.

* [SERVER-132517](https://jira.mongodb.org/browse/SERVER-132517) ([CVE-2026-120813](https://www.cve.org/CVERecord?id=CVE-2026-120813)): Fixes client-side field-level encryption (CSFLE) schema parsing that can discard encryption metadata. A crafted schema can cause CSFLE clients to store sensitive data in plaintext.

* [SERVER-133600](https://jira.mongodb.org/browse/SERVER-133600) ([CVE-2026-120814](https://www.cve.org/CVERecord?id=CVE-2026-120814)): Fixes privilege checks in sharding operations. The vulnerability permits users with shard administration privileges to modify data or security settings beyond their authorized scope.

* [SERVER-134872](https://jira.mongodb.org/browse/SERVER-134872) ([CVE-2026-120815](https://www.cve.org/CVERecord?id=CVE-2026-120815)): Fixes an authorization check that can grant administrative privileges to an unauthenticated user with local host access.

* [SERVER-135655](https://jira.mongodb.org/browse/SERVER-135655) ([CVE-2026-120817](https://www.cve.org/CVERecord?id=CVE-2026-120817)): Fixes a race condition in geospatial collection validation. Concurrent writes from authenticated users can exploit the vulnerability to terminate the server.

* [SERVER-136285](https://jira.mongodb.org/browse/SERVER-136285) ([CVE-2026-120821](https://www.cve.org/CVERecord?id=CVE-2026-120821)): Fixes an aggregation sub-pipeline memory error. Authenticated users with read privileges can exploit the vulnerability to terminate the server.

* [SERVER-136182](https://jira.mongodb.org/browse/SERVER-136182) ([CVE-2026-120822](https://www.cve.org/CVERecord?id=CVE-2026-120822)): Fixes a missing authorization check in `applyOps`. The vulnerability permits users with backup and restore privileges to read collections outside their permitted scope. These users can also relocate unauthorized collections.

* [SERVER-136505](https://jira.mongodb.org/browse/SERVER-136505) ([CVE-2026-120824](https://www.cve.org/CVERecord?id=CVE-2026-120824)): Fixes a memory error during time series bucket validation. Users with direct bucket-write privileges can exploit the vulnerability to crash the server. Exploitation can also permit arbitrary code execution.

* [SERVER-136876](https://jira.mongodb.org/browse/SERVER-136876), [SERVER-136878](https://jira.mongodb.org/browse/SERVER-136878) ([CVE-2026-120825](https://www.cve.org/CVERecord?id=CVE-2026-120825)): Fixes privilege checks for nested pipelines in view definitions. The vulnerability can expose restricted collections, including stored authentication data, to users without read access.

* [SERVER-137361](https://jira.mongodb.org/browse/SERVER-137361) ([CVE-2026-120826](https://www.cve.org/CVERecord?id=CVE-2026-120826)): Fixes view authorization in sharded deployments. The vulnerability permits cross-database reads by users with read and write privileges on one database. The databases must reside on the same shard.

* [SERVER-138119](https://jira.mongodb.org/browse/SERVER-138119) ([CVE-2026-120828](https://www.cve.org/CVERecord?id=CVE-2026-120828)): Fixes unbounded wait-record accumulation for read timestamps that a replica set member never reaches. Unauthenticated requests can exploit the vulnerability to exhaust memory.

### Medium severity

* [SERVER-132946](https://jira.mongodb.org/browse/SERVER-132946) ([CVE-2026-96297](https://www.cve.org/CVERecord?id=CVE-2026-96297)): Fixes an aggregation memory error with a batch size of `0`. The vulnerability can expose unrelated server memory in query results. The vulnerability can also terminate the server.

* [SERVER-134618](https://jira.mongodb.org/browse/SERVER-134618) ([CVE-2026-103965](https://www.cve.org/CVERecord?id=CVE-2026-103965)): Fixes aggregation query rewrites that mishandle constants. The vulnerability can expose field values outside the intended query output.

* [SERVER-134893](https://jira.mongodb.org/browse/SERVER-134893) ([CVE-2026-120819](https://www.cve.org/CVERecord?id=CVE-2026-120819)): Fixes a server-side JavaScript memory error. The vulnerability can expose limited process memory to authenticated users with read privileges.

* [SERVER-132279](https://jira.mongodb.org/browse/SERVER-132279) ([CVE-2026-120809](https://www.cve.org/CVERecord?id=CVE-2026-120809)): Fixes a memory error during time series aggregation. With a non-default query engine setting, authenticated users could read server memory or terminate the server.

* [SERVER-135353](https://jira.mongodb.org/browse/SERVER-135353) ([CVE-2026-120811](https://www.cve.org/CVERecord?id=CVE-2026-120811)): Fixes a query plan cache memory error. Diagnostic output could expose server memory to an authenticated user. The error could also terminate the server.

* [SERVER-131961](https://jira.mongodb.org/browse/SERVER-131961) ([CVE-2026-120812](https://www.cve.org/CVERecord?id=CVE-2026-120812)): Fixes a time series query error that lets authenticated users with read privileges terminate the server.

* [SERVER-135737](https://jira.mongodb.org/browse/SERVER-135737) ([CVE-2026-120820](https://www.cve.org/CVERecord?id=CVE-2026-120820)): Fixes unbounded memory use in encrypted-field statistics. Users with basic read access could cause the server to retain memory and slow down.

For all upstream fixes, see the [MongoDB 9.0 changelog :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-changelog/){:target="_blank"} and [MongoDB security bulletins :octicons-link-external-16:](https://www.mongodb.com/resources/products/alerts){:target="_blank"}.

## Known issues

The following upstream issues affect the MongoDB 9.0.8 base:

* [SERVER-136226](https://jira.mongodb.org/browse/SERVER-136226): Connection pools can exhaust config server connections. For dedicated config servers, set `ShardingTaskExecutorPoolMinSizeForConfigServers` to `1` before the upgrade if `ShardingTaskExecutorPoolMinSize` exceeds `1`.

* [SERVER-89953](https://jira.mongodb.org/browse/SERVER-89953): At FCV 9.0, explicit simple collation in `listIndexes` output can cause object-document mappers to rebuild unchanged indexes. Avoid automatic index synchronization at application startup. Review index differences before you apply changes.

* [SERVER-136961](https://jira.mongodb.org/browse/SERVER-136961): After an unclean shutdown, a node configured for file copy based initial sync can enter a crash loop. Restart the affected node with `initialSyncMethod` set to `logical` to recover.

See the [upstream known issues :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/#known-issues){:target="_blank"} for details and resolution status.

# Percona Server for MongoDB {{ page.meta.version }} ({{date.9_0_8}})

[Installation](../install/index.md){.md-button}
[Upgrade](https://www.mongodb.com/docs/manual/release-notes/9.0-upgrade-standalone/){.md-button}

Percona Server for MongoDB {{ page.meta.version }} is a drop-in replacement for MongoDB Community Edition. It supports MongoDB Community protocols and drivers and provides [enterprise-grade features at no cost](../comparison.md).

This release is based on [MongoDB 9.0.8 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/#908---nov-10-2026){:target="_blank"}. It includes upstream features and fixes through MongoDB 9.0.8, including the security fixes in earlier 9.0 patch releases.

## Upgrade considerations

Before upgrading from 8.0 or 8.3, check that your drivers support MongoDB 9.0 and [review the compatibility changes :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/){:target="_blank"}. Review server-side JavaScript that relies on the host time zone. Local `Date` operations now use UTC.

If your backup scripts call `createBackup`, migrate them to [Percona Backup for MongoDB :octicons-link-external-16:](https://docs.percona.com/percona-backup-mongodb/latest/installation.html){:target="_blank"} before upgrading. Percona Server for MongoDB 9.0 removes the `createBackup` command.

If you use the Percona Memory Engine, review your `storage.wiredTiger` settings before upgrading. The engine inherits those settings unless its own `storage.inMemory` options override them. Settings that the engine previously reset, such as compression options, can now affect its behavior.

If you use assumed roles in AWS GovCloud, China, or ISO partitions, review the permissions of existing `$external` users named with IAM role ARNs. All sessions of a matching role can now authenticate as that user. Replace users named with full STS assumed-role session ARNs with appropriately authorized IAM role-ARN users. See [Configure AWS IAM authentication](../aws-iam-setup.md).

## Release highlights

### LDAP user-to-DN caching and monitoring

Percona Server for MongoDB caches LDAP user-to-DN mappings to reduce repeated directory searches. Set the entry lifetime with `ldapUserToDNCacheTTLSeconds` (default: 30 seconds) and the maximum number of entries with `ldapUserToDNCacheSize` (default: 10,000). Set either parameter to `0` to disable the cache.

The `ldap.userToDNCache` section in `serverStatus` reports cache usage, hits, misses, and invalidations. Use these metrics to check whether the cache is sized for your workload. See [LDAP configuration parameters](../ldap-parameters.md).

### Upstream improvements

The key upstream improvements include:

#### Resource management

A query operation now has a configurable memory limit, defaulting to the greater of 1 GB or 20% of the memory available to the server process. The existing per-stage limits and spill-to-disk behavior remain in effect. See [Aggregation pipeline limits :octicons-link-external-16:](https://www.mongodb.com/docs/manual/core/aggregation-pipeline-limits/){:target="_blank"}.

The server also limits concurrently open multi-document transactions to 10,000 by default. Configure this limit with `maxConcurrentMultiDocumentTransactions`.

#### Query controls and diagnostics

You can pass `querySettings` directly to `find`, `distinct`, and `aggregate` for a single execution. Stored cluster settings take precedence when the same field is specified in both places. At feature compatibility version (FCV) 9.0, query settings also support a `maxTimeMS` limit for a query shape. See [Query settings :octicons-link-external-16:](https://www.mongodb.com/docs/manual/reference/command/setquerysettings/){:target="_blank"}.

New `serverStatus` metrics report query memory usage and change stream activity. Logical initial sync reports its current phase, transfer rate, and attempt history through `replSetGetStatus`.

#### Server-side JavaScript

The `$accumulator`, `$function`, and `$where` operators are no longer deprecated. They use a WebAssembly-based JavaScript engine with stronger isolation. Review the UTC date behavior described in [Upgrade considerations](#upgrade-considerations).

#### Time series collections and document validation

Time series collections now use a single namespace and support `renameCollection`. The new `constraint` validation level ensures that all documents satisfy the collection's validation rules, including documents already present when the constraint is enabled. See [Validation levels :octicons-link-external-16:](https://www.mongodb.com/docs/manual/core/schema-validation/specify-validation-level/){:target="_blank"}.

For the full feature list, see [Release Notes for MongoDB 9.0 :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/){:target="_blank"} and [Compatibility Changes in MongoDB 9.0 :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/){:target="_blank"}.

Other important fixes include:

* [SERVER-134533](https://jira.mongodb.org/browse/SERVER-134533): Fixed metadata inconsistencies when shard draining starts during `movePrimary`.
* [SERVER-133518](https://jira.mongodb.org/browse/SERVER-133518): Fixed a shard becoming stuck during step-up after an interrupted chunk operation, preventing it from becoming primary.
* [SERVER-127745](https://jira.mongodb.org/browse/SERVER-127745): Fixed a resharding deadlock after a rapid primary step-down and step-up.
* [SERVER-114507](https://jira.mongodb.org/browse/SERVER-114507): Fixed `$out` unexpectedly moving an unsharded output collection to the primary shard.
* [SERVER-134723](https://jira.mongodb.org/browse/SERVER-134723): Fixed a crash when a newly elected primary cannot find a synchronization source for catch-up.
* [SERVER-135249](https://jira.mongodb.org/browse/SERVER-135249): Prevented errors in change stream metrics from blocking `serverStatus` completion.

## Security fixes from upstream MongoDB

This release includes the following selected upstream security fixes. Severity categories follow MongoDB's CVSS 4.0 scores. The fixes were introduced in MongoDB 9.0.1, 9.0.4, and 9.0.7 and are included in the 9.0.8 base.

### Critical severity

* [SERVER-138119](https://jira.mongodb.org/browse/SERVER-138119), [SERVER-138175](https://jira.mongodb.org/browse/SERVER-138175) ([CVE-2026-118383](https://www.cve.org/CVERecord?id=CVE-2026-118383)): Fixed a replication memory error during primary catch-up. Unauthenticated requests could cause a replica set member to stop or, under certain conditions, execute arbitrary code. Standalone servers are not affected.

### High severity

* [SERVER-134063](https://jira.mongodb.org/browse/SERVER-134063) ([CVE-2026-89099](https://www.cve.org/CVERecord?id=CVE-2026-89099)): Fixed a race condition that could let an authenticated user with read and write privileges cause memory corruption and terminate the server.

* [SERVER-130431](https://jira.mongodb.org/browse/SERVER-130431) ([CVE-2026-96299](https://www.cve.org/CVERecord?id=CVE-2026-96299)): Fixed an aggregation authorization issue that could allow an authenticated user with read and write privileges to crash `mongos`, interrupting clients using that router.

* [SERVER-131412](https://jira.mongodb.org/browse/SERVER-131412) ([CVE-2026-104004](https://www.cve.org/CVERecord?id=CVE-2026-104004)): Fixed collection validation expressions that could cause the server to stop when an authenticated user inserts a document.

* [SERVER-131411](https://jira.mongodb.org/browse/SERVER-131411) ([CVE-2026-104005](https://www.cve.org/CVERecord?id=CVE-2026-104005)): Fixed an authorization issue involving an internal aggregation stage that could allow an authenticated user with read and write privileges to terminate `mongos`.

* [SERVER-135180](https://jira.mongodb.org/browse/SERVER-135180) ([CVE-2026-120803](https://www.cve.org/CVERecord?id=CVE-2026-120803)): Fixed a memory error in `$locf` window aggregation that could expose server memory or crash `mongod` when triggered by an authenticated user with read and write privileges.

* [SERVER-130261](https://jira.mongodb.org/browse/SERVER-130261) ([CVE-2026-120806](https://www.cve.org/CVERecord?id=CVE-2026-120806)): Fixed incomplete cleanup when roles are dropped. Recreating a role with the same name could otherwise grant its new privileges to previously associated users without an explicit grant.

* [SERVER-130169](https://jira.mongodb.org/browse/SERVER-130169) ([CVE-2026-120807](https://www.cve.org/CVERecord?id=CVE-2026-120807)): Fixed an X.509 authentication check that could grant internal privileges to a holder of a valid cluster-member certificate under specific user-lookup conditions and a non-default cluster authentication configuration.

* [SERVER-132430](https://jira.mongodb.org/browse/SERVER-132430) ([CVE-2026-120810](https://www.cve.org/CVERecord?id=CVE-2026-120810)): Bound memory use in an aggregation expression that an authenticated user with read privileges could use to exhaust server memory.

* [SERVER-132517](https://jira.mongodb.org/browse/SERVER-132517) ([CVE-2026-120813](https://www.cve.org/CVERecord?id=CVE-2026-120813)): Fixed CSFLE schema parsing that could discard encryption metadata from a crafted schema, causing data intended for encryption to be stored in plaintext.

* [SERVER-133600](https://jira.mongodb.org/browse/SERVER-133600) ([CVE-2026-120814](https://www.cve.org/CVERecord?id=CVE-2026-120814)): Fixed privilege checks in sharding operations that could allow a user with shard administration privileges to modify data or security settings beyond their authorized scope.

* [SERVER-134872](https://jira.mongodb.org/browse/SERVER-134872) ([CVE-2026-120815](https://www.cve.org/CVERecord?id=CVE-2026-120815)): Fixed an authorization check that could allow an unauthenticated user with local host access to obtain administrative privileges.

* [SERVER-135655](https://jira.mongodb.org/browse/SERVER-135655) ([CVE-2026-120817](https://www.cve.org/CVERecord?id=CVE-2026-120817)): Fixed a race condition during concurrent writes checked by geospatial collection validators that could terminate the server.

* [SERVER-136285](https://jira.mongodb.org/browse/SERVER-136285) ([CVE-2026-120821](https://www.cve.org/CVERecord?id=CVE-2026-120821)): Fixed a memory error in aggregation sub-pipelines that an authenticated user with read privileges could trigger to terminate the server.

* [SERVER-136182](https://jira.mongodb.org/browse/SERVER-136182) ([CVE-2026-120822](https://www.cve.org/CVERecord?id=CVE-2026-120822)): Fixed a missing authorization check in `applyOps`. A user with backup and restore privileges could otherwise read or relocate collections outside their permitted scope.

* [SERVER-136505](https://jira.mongodb.org/browse/SERVER-136505) ([CVE-2026-120824](https://www.cve.org/CVERecord?id=CVE-2026-120824)): Fixed a memory error during time series bucket validation. A user allowed to write bucket documents directly could cause a crash or, under certain conditions, arbitrary code execution.

* [SERVER-136876](https://jira.mongodb.org/browse/SERVER-136876), [SERVER-136878](https://jira.mongodb.org/browse/SERVER-136878) ([CVE-2026-120825](https://www.cve.org/CVERecord?id=CVE-2026-120825)): Fixed privilege checks for nested pipelines in view definitions that could expose collections, including stored authentication data, to users without read access.

* [SERVER-137361](https://jira.mongodb.org/browse/SERVER-137361) ([CVE-2026-120826](https://www.cve.org/CVERecord?id=CVE-2026-120826)): Fixed view authorization in sharded deployments that could allow a user with read and write privileges on one database to read other databases on the same shard.

* [SERVER-138119](https://jira.mongodb.org/browse/SERVER-138119) ([CVE-2026-120828](https://www.cve.org/CVERecord?id=CVE-2026-120828)): Fixed unbounded accumulation of wait records for a read timestamp the replica set member never reaches. Unauthenticated requests could exhaust memory and make the server unavailable.

### Medium severity

* [SERVER-132946](https://jira.mongodb.org/browse/SERVER-132946) ([CVE-2026-96297](https://www.cve.org/CVERecord?id=CVE-2026-96297)): Fixed an aggregation memory error with a batch size of `0` that could return unrelated server memory in query results or terminate the server.

* [SERVER-134618](https://jira.mongodb.org/browse/SERVER-134618) ([CVE-2026-103965](https://www.cve.org/CVERecord?id=CVE-2026-103965)): Fixed handling of constants during aggregation query rewriting that could return field values the query did not intend to expose.

* [SERVER-134893](https://jira.mongodb.org/browse/SERVER-134893) ([CVE-2026-120819](https://www.cve.org/CVERecord?id=CVE-2026-120819)): Fixed a server-side JavaScript memory error that could expose a limited amount of process memory to an authenticated user with read privileges.

For all upstream fixes, see the [MongoDB 9.0 changelog :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-changelog/){:target="_blank"} and [MongoDB security bulletins :octicons-link-external-16:](https://www.mongodb.com/resources/products/alerts){:target="_blank"}.

## Known issues

The following upstream issues affect the MongoDB 9.0.8 base:

* [SERVER-136226](https://jira.mongodb.org/browse/SERVER-136226): Connection pools can exhaust config server connections. For dedicated config servers, set `ShardingTaskExecutorPoolMinSizeForConfigServers` to `1` before upgrading if `ShardingTaskExecutorPoolMinSize` exceeds `1`.
* [SERVER-89953](https://jira.mongodb.org/browse/SERVER-89953): At FCV 9.0, explicit simple collation in `listIndexes` output can cause object-document mappers to rebuild unchanged indexes. Avoid automatic index synchronization at application startup; review index differences before applying changes.
* [SERVER-136961](https://jira.mongodb.org/browse/SERVER-136961): After an unclean shutdown, a node using file copy based initial sync can enter a crash loop. Restart the affected node with `initialSyncMethod` set to `logical` to recover.

See the [upstream known issues :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/#known-issues){:target="_blank"} for details and resolution status.

## Changelog

### New features

* [PSMDB-2003](https://perconadev.atlassian.net/browse/PSMDB-2003): Added LDAP user-to-DN caching with a configurable entry lifetime and maximum cache size.

### Improvements

* [PSMDB-1832](https://perconadev.atlassian.net/browse/PSMDB-1832): Updated the Percona Memory Engine to inherit WiredTiger options unless the memory engine overrides them. See [Percona Memory Engine](../inmemory.md).
* [PSMDB-2038](https://perconadev.atlassian.net/browse/PSMDB-2038): Added LDAP user-to-DN cache metrics to `serverStatus`.

### Bugs fixed

* [PSMDB-1766](https://perconadev.atlassian.net/browse/PSMDB-1766): Fixed an issue that prevented the LDAP user cache from refreshing. Changes to a user's LDAP roles now take effect according to the configured [LDAP cache refresh strategy](../authorization.md#ldap-cache-refresh-parameters).
* [PSMDB-1937](https://perconadev.atlassian.net/browse/PSMDB-1937): Fixed an issue that caused source builds to fail when the source directory did not contain a `.git` directory.
* [PSMDB-2200](https://perconadev.atlassian.net/browse/PSMDB-2200): Fixed duplicate-symbol errors that caused statically linked builds to fail.
* [PSMDB-2279](https://perconadev.atlassian.net/browse/PSMDB-2279): Fixed AWS IAM authentication for assumed roles in non-commercial AWS partitions. The server preserves the partition when converting the session ARN to the IAM role ARN used to look up the user in `$external`.

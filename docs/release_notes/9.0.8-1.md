# Percona Server for MongoDB {{ page.meta.version }} ({{date.9_0_8}})

[Installation](../install/index.md){.md-button}
[Upgrade](https://www.mongodb.com/docs/manual/release-notes/9.0-upgrade-standalone/){.md-button}

We are pleased to announce Percona Server for MongoDB {{ page.meta.version }}, the first release in the 9.0 series. Percona Server for MongoDB is a drop-in replacement for MongoDB Community Edition. The server supports MongoDB Community protocols and drivers and provides [enterprise-grade features for free](../comparison.md). These features help you meet your organization's requirements for high availability, reliability, and data security.

This release includes the improvements and bug fixes from [MongoDB 9.0.0 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/#900---sept-28-2026){:target="_blank"} through [MongoDB 9.0.8 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/#908---nov-10-2026){:target="_blank"}.

Percona Memory Engine adapts to the WiredTiger settings in MongoDB 9.0. Review your WiredTiger configuration before you upgrade. The release also removes the `createBackup` command, deprecated in 8.3.17-5. See [Upgrade considerations](#upgrade-considerations) for the required changes.

## Upgrade considerations

Before you upgrade, read the [MongoDB 9.0 compatibility changes :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/){:target="_blank"}. Confirm that your drivers support 9.0. Check the following Percona-specific changes:

### `createBackup` command removed

The `createBackup` command was deprecated in 8.3.17-5 and no longer exists in 9.0. If your scripts call `createBackup`, migrate those scripts to [Percona Backup for MongoDB :octicons-link-external-16:](https://docs.percona.com/percona-backup-mongodb/latest/installation.html){:target="_blank"} before you upgrade.

### Percona Memory Engine settings

Percona Memory Engine uses more of your WiredTiger settings. Compression options under `storage.wiredTiger`, such as `blockCompressor`, `zstdCompressionLevel`, and `prefixCompression`, apply to Percona Memory Engine too. Earlier versions ignored them. If your configuration file has a `storage.wiredTiger` section, review that section before you switch to Percona Memory Engine. See [Percona Memory Engine configuration](#percona-memory-engine-configuration).

### AWS IAM role users outside the commercial partition

This change affects MONGODB-AWS authentication in AWS GovCloud, China, and other non-commercial partitions. Assumed-role sessions authenticate as the `$external` user whose name matches the IAM role ARN. Commercial regions use the same authentication behavior. This change has two effects:

* Every session of a role can use an existing role ARN user, such as `arn:aws-us-gov:iam::<account_id>:role/<role_name>`. Check the privileges of these users before you upgrade.

* Users whose names contain a full STS session ARN no longer match assumed-role sessions. Those users cannot authenticate. Replace those users with role ARN users.

See [Configure AWS IAM authentication](../aws-iam-setup.md) for the user format.

## Release highlights

### Percona Memory Engine configuration

Percona Memory Engine inherits your `storage.wiredTiger` settings, with a few exceptions. Memory size, the statistics logging interval, and custom configuration strings always come from `storage.inMemory`. If you omit one of those settings, Percona Memory Engine uses its own default rather than the WiredTiger value.

Percona Memory Engine inherits the compression settings. These include the collection block compressor, the Zstandard compression level, and index prefix compression. Percona Memory Engine ignores settings for journaling, checkpoints, and live restore. Those settings do not apply to an in-memory engine.

For the full list of inherited, replaced, and ignored settings, see [How WiredTiger settings apply](../inmemory.md#how-wiredtiger-settings-apply).

## Upstream improvements

MongoDB 9.0 includes the following improvements. For the complete list, see [Release Notes for MongoDB 9.0 :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/){:target="_blank"}.

### Resource management

A single query operation has a memory limit. The default limit is one GB or 20% of the memory available to the server process, whichever is greater. Queries that exceed the limit fail with an `ExceededMemoryLimit` error. You can adjust the limit with `internalQueryMaxMemoryUsageBytesPerOperation`. The existing 100 MB per-stage limit and spill-to-disk behavior remain unchanged. See [Aggregation pipeline limits :octicons-link-external-16:](https://www.mongodb.com/docs/manual/core/aggregation-pipeline-limits/){:target="_blank"}.

The server also limits how many multi-document transactions external clients can keep open at once. The default limit is 10,000. You can change the limit with `maxConcurrentMultiDocumentTransactions`. When the server reaches the limit, additional transactions fail with a `TooManyOpenTransactions` error.

### Query controls and diagnostics

You can pass `querySettings` directly to a `find`, `distinct`, or `aggregate` command. These settings apply to that execution only. The cluster does not store these settings. For the same query shape, cluster query settings override command-level settings that specify the same field. With feature compatibility version (FCV) 9.0, you can also set `maxTimeMS` for a query shape with `setQuerySettings`. See [Query settings :octicons-link-external-16:](https://www.mongodb.com/docs/manual/reference/command/setquerysettings/){:target="_blank"}.

Additional diagnostic details include:

* `serverStatus` reports query memory usage and change stream cursor activity.

* Query statistics cover `insert`, `update`, and `delete` commands.

* During logical initial sync, `replSetGetStatus` shows the active phase, transfer rate, and attempt history.

### Server-side JavaScript

`$accumulator`, `$function`, and `$where` are no longer deprecated. These operators run on a WebAssembly-based JavaScript engine with stronger isolation.

The JavaScript engine evaluates local `Date` operations in UTC, regardless of the host time zone. Code that calls methods such as `getHours()` can return different results after the upgrade. Review the [JavaScript compatibility changes :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/){:target="_blank"} before you upgrade.

### Time series collections and document validation

MongoDB stores time series collections as a single namespace. You can rename time series collections with `renameCollection`. If a database holds more than 5,000 time series collections, expect a longer upgrade. Such databases can also experience write latency spikes during the upgrade.

The `constraint` validation level applies your validation rules to every insert and update. This validation level guarantees that every document in the collection satisfies those rules. The guarantee covers existing documents too. See [Validation levels :octicons-link-external-16:](https://www.mongodb.com/docs/manual/core/schema-validation/specify-validation-level/){:target="_blank"}.

* [SERVER-134723](https://jira.mongodb.org/browse/SERVER-134723): Prevents a crash when a newly elected primary can't find a sync source for catch-up.

* [SERVER-135249](https://jira.mongodb.org/browse/SERVER-135249): Prevents change stream metric errors that block `serverStatus`.

## Security fixes from upstream MongoDB

MongoDB 9.0.8 includes every security fix from the earlier 9.0 patch releases. The following fixes apply to Percona Server for MongoDB. Severity levels follow MongoDB's CVSS 4.0 ratings.

### Critical severity

* [SERVER-138119](https://jira.mongodb.org/browse/SERVER-138119), [SERVER-138175](https://jira.mongodb.org/browse/SERVER-138175) ([CVE-2026-118383](https://www.cve.org/CVERecord?id=CVE-2026-118383)): Fixes a memory error during primary catch-up in replica sets. Without the fix, an unauthenticated attacker could exploit the error to crash replica set members. The error could also enable arbitrary code execution. The error does not affect standalone servers.

### High severity

* [SERVER-130431](https://jira.mongodb.org/browse/SERVER-130431) ([CVE-2026-96299](https://www.cve.org/CVERecord?id=CVE-2026-96299)): Adds a missing authorization check to an internal aggregation stage. Without the check, an authenticated user with read and write privileges could crash `mongos`.

* [SERVER-131412](https://jira.mongodb.org/browse/SERVER-131412) ([CVE-2026-104004](https://www.cve.org/CVERecord?id=CVE-2026-104004)): Fixes collection validators that could crash the server when an authenticated user inserts a document.

* [SERVER-131411](https://jira.mongodb.org/browse/SERVER-131411) ([CVE-2026-104005](https://www.cve.org/CVERecord?id=CVE-2026-104005)): Fixes authorization for bulk writes routed through `mongos`. Without the fix, an authenticated user with write access to a regular collection can target internal system namespaces. The router accepts those bulk writes without the required namespace authorization.

* [SERVER-135180](https://jira.mongodb.org/browse/SERVER-135180) ([CVE-2026-120803](https://www.cve.org/CVERecord?id=CVE-2026-120803)): Fixes a memory error in the `$locf` window operator. Without the fix, an authenticated user with read and write privileges could exploit the error to expose server memory. The error could also crash `mongod`.

* [SERVER-130261](https://jira.mongodb.org/browse/SERVER-130261) ([CVE-2026-120806](https://www.cve.org/CVERecord?id=CVE-2026-120806)): Fixes incomplete cleanup when roles are dropped. Without the fix, stale role references could grant unintended privileges once a role with the same name was recreated.

* [SERVER-130169](https://jira.mongodb.org/browse/SERVER-130169) ([CVE-2026-120807](https://www.cve.org/CVERecord?id=CVE-2026-120807)): Fixes an X.509 cluster membership check that could grant internal privileges. Exploitation requires a valid cluster member certificate, specific user lookup conditions, and a non-default cluster authentication configuration.

* [SERVER-132430](https://jira.mongodb.org/browse/SERVER-132430) ([CVE-2026-120810](https://www.cve.org/CVERecord?id=CVE-2026-120810)): Limits memory use in an aggregation expression. Without the limit, an authenticated user with read privileges could use the expression to exhaust server memory.

* [SERVER-132517](https://jira.mongodb.org/browse/SERVER-132517) ([CVE-2026-120813](https://www.cve.org/CVERecord?id=CVE-2026-120813)): Fixes client-side field level encryption (CSFLE) schema parsing. Without the fix, a crafted schema with duplicate keys could cause CSFLE clients to discard encryption metadata. The clients could then store sensitive fields in plaintext.

* [SERVER-133600](https://jira.mongodb.org/browse/SERVER-133600) ([CVE-2026-120814](https://www.cve.org/CVERecord?id=CVE-2026-120814)): Fixes privilege checks in sharding operations. A user with shard administration privileges could otherwise create a persistent cluster-wide root user.

* [SERVER-134872](https://jira.mongodb.org/browse/SERVER-134872) ([CVE-2026-120815](https://www.cve.org/CVERecord?id=CVE-2026-120815)): Fixes the localhost exception, which could stay active after an `$external` user was created and give an unauthenticated local connection administrative access.

* [SERVER-135655](https://jira.mongodb.org/browse/SERVER-135655) ([CVE-2026-120817](https://www.cve.org/CVERecord?id=CVE-2026-120817)): Fixes a race condition in geospatial schema validation. Concurrent writes from authenticated users could crash the server.

* [SERVER-136285](https://jira.mongodb.org/browse/SERVER-136285) ([CVE-2026-120821](https://www.cve.org/CVERecord?id=CVE-2026-120821)): Fixes a memory error in aggregation sub-pipelines. Without the fix, an authenticated user with read privileges could exploit the error to crash the server.

* [SERVER-136182](https://jira.mongodb.org/browse/SERVER-136182) ([CVE-2026-120822](https://www.cve.org/CVERecord?id=CVE-2026-120822)): Adds a missing authorization check to `applyOps`. Without the check, users with backup and restore privileges could read collections outside their permitted scope. Those users could also relocate collections without the required authorization.

* [SERVER-136505](https://jira.mongodb.org/browse/SERVER-136505) ([CVE-2026-120824](https://www.cve.org/CVERecord?id=CVE-2026-120824)): Fixes a memory error in time series bucket validation. Without the fix, a user with direct write access to buckets could crash the server. The error could also enable arbitrary code execution.

* [SERVER-136876](https://jira.mongodb.org/browse/SERVER-136876), [SERVER-136878](https://jira.mongodb.org/browse/SERVER-136878) ([CVE-2026-120825](https://www.cve.org/CVERecord?id=CVE-2026-120825)): Fixes privilege checks for nested pipelines in view definitions. * [SERVER-137361](https://jira.mongodb.org/browse/SERVER-137361) ([CVE-2026-120826](https://www.cve.org/CVERecord?id=CVE-2026-120826)): Fixes view authorization in sharded clusters. Without the fix, users with read and write privileges on one database could read another database on the same shard.

* [SERVER-138119](https://jira.mongodb.org/browse/SERVER-138119) ([CVE-2026-120828](https://www.cve.org/CVERecord?id=CVE-2026-120828)): Fixes unbounded memory growth when clients request a read timestamp that a replica set member never reaches. ## Known issues

These upstream issues are still open in MongoDB 9.0.8:

* [SERVER-136226](https://jira.mongodb.org/browse/SERVER-136226): Each node opens at least `ShardingTaskExecutorPoolMinSize` connections to every config server. These connections can exhaust config server connections. If you use dedicated config servers, check whether `ShardingTaskExecutorPoolMinSize` exceeds `1` before you upgrade. If so, set `ShardingTaskExecutorPoolMinSizeForConfigServers` to `1`.

* [SERVER-89953](https://jira.mongodb.org/browse/SERVER-89953): At FCV 9.0, `listIndexes` shows the simple collation explicitly. Some object-document mappers (ODMs) read that as a change and drop and rebuild indexes that haven't changed. Don't sync indexes automatically when your application starts. Instead, review the index differences and apply them as a separate deployment step. If you use Mongoose, upgrade to 9.10.4 or 8.24.5.

* [SERVER-136961](https://jira.mongodb.org/browse/SERVER-136961): After an unclean shutdown, a node configured for file copy based initial sync can crash on restart. To recover, restart the node with `initialSyncMethod` set to `logical`.

Check [MongoDB 9.0 known issues :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/9.0/#known-issues){:target="_blank"} for updates.

## Changelog

### Features

* [PSMDB-2003](https://perconadev.atlassian.net/browse/PSMDB-2003): Caches LDAP user-to-DN mappings to reduce LDAP lookups during authentication. You can tune the cache with `ldapUserToDNCacheTTLSeconds` and `ldapUserToDNCacheSize`.

### Improvements

* [PSMDB-1832](https://perconadev.atlassian.net/browse/PSMDB-1832): Percona Memory Engine inherits `storage.wiredTiger` settings, except those that `storage.inMemory` options replace. See [Percona Memory Engine](../inmemory.md).

* [PSMDB-2038](https://perconadev.atlassian.net/browse/PSMDB-2038): Adds LDAP user-to-DN cache metrics to `serverStatus` under `ldap.userToDNCache`.

* [PSMDB-2150](https://perconadev.atlassian.net/browse/PSMDB-2150), [PSMDB-2257](https://perconadev.atlassian.net/browse/PSMDB-2257): Binary packages, Docker images, and tarballs include a [software bill of materials (SBOM)](../sbom.md).

### Removed features

* [PSMDB-2291](https://perconadev.atlassian.net/browse/PSMDB-2291): Removes the `createBackup` command. Use Percona Backup for MongoDB instead.

### Fixed bugs

* [PSMDB-1766](https://perconadev.atlassian.net/browse/PSMDB-1766): Fixes LDAP user cache invalidation. The server didn't clear cached `$external` users at the `ldapUserCacheInvalidationInterval`, so role changes in LDAP weren't picked up. See [LDAP cache refresh parameters](../authorization.md#ldap-cache-refresh-parameters).

* [PSMDB-2279](https://perconadev.atlassian.net/browse/PSMDB-2279): Fixes MONGODB-AWS authentication for assumed roles in AWS GovCloud, China, and other non-commercial partitions. The server now keeps the ARN's partition when it maps an assumed-role session to its IAM role.

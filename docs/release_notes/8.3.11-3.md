# Percona Server for MongoDB {{ page.meta.version }} ({{ date[(release.split('-')[0].replace('.', '') | int)] }})

[Installation](../install/index.md){.md-button}
[Upgrade from MongoDB Community](../install/upgrade-from-mongodb.md){.md-button}

Percona Server for MongoDB {{ page.meta.version }} is an enhanced, source-available, and highly scalable database that is a fully compatible, drop-in replacement for MongoDB Community Edition.

Percona Server for MongoDB **{{ page.meta.version }}** includes the improvements and bug fixes of:

- [MongoDB 8.3.11 Community Edition :octicons-link-external-16:](https://www.mongodb.com/docs/manual/release-notes/8.3/){:target="_blank"}.

- Supports protocols and drivers of MongoDB Community **8.3.11**.

## Upgrade recommendation

This release fixes one critical, fourteen high-severity, five medium-severity, and one low-severity vulnerability inherited from upstream MongoDB, all of which affect earlier Percona Server for MongoDB 8.3.x versions. We strongly recommend upgrading to version {{ page.meta.version }} as soon as possible.

The critical issue is the most urgent. Under specific configuration conditions, the authorization subsystem can remain disabled when the server starts, which lets any unauthenticated party with network access perform arbitrary administrative operations. Two further issues are reachable without authentication and can deny service on a `mongos` router or a replica set member. Most of the remaining fixes require only ordinary `readWrite` or read-only privileges, so deployments that grant broad database access to application accounts should treat this upgrade as a priority.

## Security fixes from upstream MongoDB

This release fixes vulnerabilities inherited from upstream MongoDB. The severity categories below follow the upstream [CVSS scores :octicons-link-external-16:](https://nvd.nist.gov/vuln-metrics/cvss){:target="_blank"}.

### Critical severity

- [SERVER-131229 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131229){:target="_blank"} ([CVE-2026-82067 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82067){:target="_blank"}): Fixed improper handling of case sensitivity in configuration validation, which could leave the authorization subsystem in its default disabled state when the server started. On an affected deployment, an unauthenticated user with network access could perform arbitrary administrative operations, fully compromising the confidentiality, integrity, and availability of the data.

### High severity

- [SERVER-132650 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132650){:target="_blank"} ([CVE-2026-82075 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82075){:target="_blank"}): Fixed an issue in the request-handling path of the `mongos` router where connection-monitoring parameters were processed without rate limiting. A client with network access to a router port and no credentials could consume CPU resources unchecked, degrading or denying service to legitimate clients.

- [SERVER-130759 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130759){:target="_blank"} ([CVE-2026-82064 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82064){:target="_blank"}): Fixed an assertion in read concern processing whose assumptions about internal state did not hold for all replica set member configurations. An unauthenticated network user could reach this assertion and terminate the affected member process.

- [SERVER-130785 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130785){:target="_blank"} ([CVE-2026-82053 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82053){:target="_blank"}): Fixed incorrect session handling in the LDAP authorization integration, where pooled LDAP connections could cause roles to be assigned incorrectly. A user could receive privileges other than those their LDAP group membership grants.

- [SERVER-130907 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130907){:target="_blank"} ([CVE-2026-82061 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82061){:target="_blank"}): Fixed a use-after-free in the query execution memory tracking subsystem. An authenticated user with read privileges could write to freed heap memory through a sequence of ordinary database commands, crashing the server or corrupting memory.

- [SERVER-131860 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131860){:target="_blank"} ([CVE-2026-82071 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82071){:target="_blank"}): Fixed insufficient validation of storage engine configuration options, where an authenticated user with write privileges could supply crafted parameters during collection creation that overrode internal storage metadata. This caused an out-of-bounds write and crashed the server, with potential for further impact including arbitrary code execution.

- [SERVER-131326 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131326){:target="_blank"} ([CVE-2026-82068 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82068){:target="_blank"}): Fixed handling of repeated statement IDs in retryable write commands. An authenticated user with write privileges could trigger a fatal assertion that recurred after restart, requiring operator intervention to clear.

- [SERVER-131423 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131423){:target="_blank"} ([CVE-2026-82070 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82070){:target="_blank"}): Fixed an issue in the diagnostic reporting interface where credentials were not redacted, although the same values were correctly redacted in the server log. A user with an authenticated session and monitoring-level permissions could read the exposed credentials.

- [SERVER-131138 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131138){:target="_blank"} ([CVE-2026-82062 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82062){:target="_blank"}): Fixed a feature gate bypass in the `applyOps` command, where an internal replication mode value that was not meant to be client-selectable enabled container operations that are disabled by default. Because the authorization check validated only the namespace and not the storage target, a user with elevated internal privileges could write directly to arbitrary internal storage tables.

- [SERVER-132125 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132125){:target="_blank"} ([CVE-2026-82073 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82073){:target="_blank"}): Fixed insufficient validation of an internal aggregation command parameter that external clients could set, causing a view-level authorization check to be skipped. When Atlas Search features were in use, an authenticated user with limited read privileges could read data from collections they were not authorized to access.

- [SERVER-130901 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130901){:target="_blank"} ([CVE-2026-82054 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82054){:target="_blank"}): Fixed unbounded iteration and allocation in the JSON Pointer parser used for `$jsonSchema` query filters. A crafted filter on a `find` command amplified memory use enough that, under concurrent load, the out-of-memory handler terminated the `mongod` process.

- [SERVER-130495 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130495){:target="_blank"} ([CVE-2026-82057 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82057){:target="_blank"}): Fixed a type confusion in the storage engine layer, where an authenticated user with `readWrite` privileges could specify an incompatible custom WiredTiger configuration option at collection creation. Reads from the misconfigured collection then crashed the server, and the configuration persisted across restarts until an operator intervened.

- [SERVER-130202 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130202){:target="_blank"} ([CVE-2026-82055 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82055){:target="_blank"}): Fixed a null pointer dereference in `2dsphere` index key generation. Inserting a crafted GeoJSON document left an internal object partially initialized, and the subsequent index key generation terminated the `mongod` process. Write access was sufficient to trigger it.

- [SERVER-127985 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-127985){:target="_blank"} ([CVE-2026-82052 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82052){:target="_blank"}): Fixed handling of regular expression matches that began part-way through a multi-byte UTF-8 character. An authenticated user able to run aggregation pipeline stages could use `$regexFindAll` to trigger an assertion during query execution and crash `mongod`.

- [SERVER-134063 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-134063){:target="_blank"} ([CVE-2026-89099 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-89099){:target="_blank"}): Fixed a race condition in the document value layer where concurrent server threads could operate on the same internal memory without synchronization, leading to memory corruption. An authenticated user with ordinary `readWrite` privileges on a database could trigger this over the normal client protocol, terminating the `mongod` process and potentially corrupting process memory with user-influenced content.

### Medium severity

- [SERVER-130306 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130306){:target="_blank"} ([CVE-2026-82056 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82056){:target="_blank"}): Fixed a race condition in text index query parsing that could dereference a pointer to text index metadata after the underlying structures had been freed. An authenticated user with `readWrite` privileges could crash the server by combining text search with concurrent index management operations.

- [SERVER-130571 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-130571){:target="_blank"} ([CVE-2026-82059 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82059){:target="_blank"}): Fixed an internal aggregation expression that was registered as accessible to any authenticated user rather than restricted to internal cluster operations. A read-only user could supply a malformed index specification and trigger an assertion failure in index key generation, terminating the process on some builds.

- [SERVER-131870 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131870){:target="_blank"} ([CVE-2026-82063 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82063){:target="_blank"}): Fixed a use-after-free in cursor management, where a stale pointer to a freed resource could be retained and dereferenced during cursor cleanup. Under specific timing conditions an authenticated user could crash the server process.

- [SERVER-131562 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131562){:target="_blank"} ([CVE-2026-82066 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82066){:target="_blank"}): Fixed a heap out-of-bounds read caused by mis-indexed tie-break vectors in the query multi-planner. An authenticated user with read and write privileges could trigger it with crafted queries and disclose adjacent heap memory.

- [SERVER-132835 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-132835){:target="_blank"} ([CVE-2026-82069 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82069){:target="_blank"}): Fixed incomplete redaction of query literals when query statistics were serialized on the `mongos` router. Query shapes for `$search` retained raw literal values, exposing other users' search terms to anyone able to read query statistics.

### Low severity

- [SERVER-131202 :octicons-link-external-16:](https://jira.mongodb.org/browse/SERVER-131202){:target="_blank"} ([CVE-2026-82060 :octicons-link-external-16:](https://www.cve.org/CVERecord?id=CVE-2026-82060){:target="_blank"}): Fixed insufficient validation of shard key values, which let an authenticated user store operator-shaped objects as shard key values in a sharded collection. When change stream events for those documents were processed in `updateLookup` mode, the values were interpreted as query operators in the internal post-image lookup, returning incorrect documents or making the stream non-resumable.
